## 一、执行摘要

核心问题不是“模型不聪明”或“审核太严格”，而是**授权、影响分析、派发、退出、业务观察、恢复和 UI 投影没有始终消费一致的事实**。

这产生两类同时存在的问题：

1. **误阻断**：查询的正常非零退出、未派发失败、重复观察、报告未 verified 被升级为风险锁或会话暂停；即使用户批准，操作仍可能走不下去。
2. **漏边界**：配置身份变化可能丢失原风险域；摘要可能被当作明确用户授权；凭据/配置部分保存、流式脱敏和数据生命周期存在可复现缺口。

整改方向是：**保留 SafetyGate 和后端权威，统一事实契约，补可靠的业务工具与恢复闭环；UI 同步改善，不用提示词、白名单扩张、换皮或扩大 root 权限代替产品修复。**

## 四、用户最关心的五条主线

### 1. “每条命令都要问，批准后还走不下去”

已定位并隔离复现，不是单纯提示词问题：

- 一些诊断被安全层视为无变更，预检/结果层却按潜在写入处理。
- `grep` 无匹配、服务 inactive 等非零退出可能生成未决变更锁；不能把退出码直接翻译成副作用。
- 重复 `ss` 等观察可能命中重放保护；用户明确新操作又可能受上轮报告未 verified 牵制。
- 已知资源冲突或不支持条件可能在批准后才被发现。
- 审核、审计回调和会话暂停耦合，一次局部失败扩大成整轮阻断。

修复重点：A05–A06、B01–B08、E03。**不采用全放行、无限白名单或取消未知结果保护。**

### 2. AI 工具与 root

模型应提出业务和身份需求，后端负责机制：

- 命令的 `privilege=root`、服务的 `sudo=true`、文件的 legacy `sessionId` 应收敛为一致的操作级权限契约。
- 已复现服务日志忽略 sudo 意图、文件接受不支持的 privilege 额外字段等差异。
- 普通 root 命令已有 UID 校验、sudo 和可信未启动条件下的替代身份路线，这些应复用，不重建万能 root Shell。
- SFTP 不因 Shell 提权就变成 root；现有拒绝该误用的限制应保留。
- 远端文件目标接口是受限读取 → 后端准备差异/版本 → 以 editId 条件提交 → 验证/恢复；这些接口**尚未实现**。
- 不让模型拿脱敏/截断文件重建覆盖原文，也不让它自行承担暂存、owner/group/mode/ACL/xattr、竞态和清理事务。
- 保留受审计 run_remote；只补少量完整业务工具，不做每条 Shell 命令的包装器。

### 3. 提前告诉 AI 系统/架构的环境组件

已有探测→缓存→模型上下文链，应改进而非推倒：

- 基础 OS/架构不能以 Python 作为唯一引导依赖；允许逐字段未知，不能整个探测一失败就只剩模糊 unavailable。
- 实际执行 PATH、身份与 cwd 必须与模型收到的信息相符；原始架构与归一化架构、内核与用户空间分开。
- 程序存在、daemon 可达、身份可访问和当前状态分开；按事实类型缓存、按连接/身份变化失效。
- 先给短小可靠的基础事实，业务能力按需补充，不每轮全机扫描。
- **无 Python 的基础信息降级，不等于整个 Agent 执行通道已经支持无 Python。**执行通道的真实依赖应明确报告，不靠任意 Shell 或不安全认证兜底。

### 4. AI 新建和使用终端

现有自动池化、忙闲分离、代次/所有权校验和 host 风险锁应保留。新增重点：

- 暂停/失败的空闲释放可能直接转人工，并开启交互 Shell；人工条目不复用但继续占池容量。
- 隔离池级测试中，4 次 acquire→releaseIdle 保留 4 个空闲 human 条目，第 5 次分配报上限。**不是正常回答四轮必坏**；answered 正常完成有复用路径。
- 仅对终端 A 调 Ctrl+C 的控制方法，会给同会话 A/B 的 pending 通道都发停止输入。
- 后台卡现有整会话停止文案和确认是明确的，不能说它没有提示；缺口是局部控制入口与一致契约。
- 已有精确 `stop_remote_job`，应复用其后端目标绑定，不再造任意 PID/kill 工具。
- 窗口不是持久 Shell；跨调用不继承 cd/export/source，人工接管也不是恢复原 Agent Shell。

目标：释放租约、保留历史、回收资源、人工接管、停止模型、停止单任务、关闭窗口和确认退出分开。不能抢回真正人工终端、关闭仍运行/未知通道或沿用旧批准。

### 5. AI UI 与 Trae CN 对标

参考边界为已有 Trae CN 3.4.9 静态 IDE 侧栏资料，不是最新版、国际版/SOLO 或逐像素运行验证。

- 正文只在 message_end 投影的链路已被真实 adapter＋合成 SSE 确认，需要全链路增量，不是 CSS 假流式。
- 已有安全 Markdown，不是从零重做解析器；补排版、语法高亮、长代码展开/换行、表格与消息操作。
- 回答为主，思考/工具次级，诊断按需；无活动不占空卡，风险和审批关键范围仍清楚。
- 运行态发送与停止分开，保留 IME、草稿、引用、后端投递路由；Enter 已能补充，不能说现有功能完全缺失。
- AI 消息上翻保护已存在，应保留；终端强制滚底是另一处问题。
- 高频小更新不能继续搬全历史、解密凭据；正文流式 U01 与增量性能 U11 同步设计。

12 包：U01 真流式；U02 Markdown；U03 代码块；U04 表格/长内容；U05 对话/过程层级；U06 风险/控制；U07 Composer；U08 消息/证据操作；U09 滚动/选择；U10 视觉/可访问性；U11 增量性能；U12 验收。

## 六、后续必须通过的三条业务链

1. **诊断链**：环境事实 → 服务状态 → 有界日志 → 重复查询 → 结论与证据。
2. **变更链**：文件版本/元数据 → diff → 审核 → 条件写入 → 配置检查 → 服务动作 → 独立验证。
3. **后台链**：启动 → 增量观察 → 单任务停止 → 真实退出核验；回答完成、abort 和信号回执都不等于进程退出。

环境矩阵还包括：无 Python、不同 PATH、UID0/普通用户、免密/有密码 sudo、sudo 缺失、PAM/MFA、取消/断线、非普通文件、链接/路径变化、元数据/并发/恢复失败；UI 覆盖深浅主题、窄栏、长历史、缩放、IME 和选择稳定性。

### 预算与思考档

- 首轮约定：**总计最多 6 次实际模型请求，每次输出最多 1024 tokens**；额外审核、连接测试和重试同计，失败止损。三档合计，不是每档 6 次。
- 本地模型目录与官方文档核对：支持 off/low/high/max；界面关闭/低/高/最高。medium 在官方接口映射到 high，不是独立档。实际服务端行为仍待验收。
- 目录给 Flash 的最大输出为 384000；这是能力/允许上限，**不代表每次实际生成这么多**。当前会话输出预算依赖目录，不能直接启动后只靠提示词把费用压低。
- **付费出站的 6 次/1024 硬限制与输入规模保护尚未完成，不得宣称已具备。**已经验证的是配置阶段禁止联网，不是后续实时计费限流器。
- 高档被 1024 截断必须单独记录，不能当作模型能力差；小样本不能得出统计性优劣结论。
