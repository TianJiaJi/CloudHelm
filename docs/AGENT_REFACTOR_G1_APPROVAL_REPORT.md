# Agent 重构 G1-C · 单一审批等待权威

> 状态：本批实现与本地验证完成。范围依据 [实施计划](V5_3_REFACTOR_PLAN.md)与[工程契约](V5_3_ENGINEERING_BOUNDARIES_PROPOSAL.md)。承接 [G1-B](AGENT_REFACTOR_G1_CONTINUITY_REPORT.md)，不是整个 G1 完成或真实环境验收。

## 本批目标

将审批 pending、提醒/硬截止、续期、取消及答复消费从 WorkerServer 移入 Application，消除装配层的审批业务计时器。Worker 只做 RPC/事件转换；SafetyGate 的精确操作绑定、执行前复核和操作提交 ACK 仍保留在原链路，不引入第二条派发路线。

## 变更

- Core 新增审批等待绑定契约：审批/操作/任务/主机/指纹、软硬期限及续期计数；不包含 UI 内容或执行能力。
- `packages/application/src/approval-coordinator.ts` 成为唯一等待权威，泛型保留上层投影但不导入 Contracts。对外只返回决定，不授予派发权。
- WorkerServer 移除 pending map、计时与受理分支，转交 Application；主机策略、会话档位和审核配置变化按原作用域取消等待。
- 期限必须为安全整数且硬截止不早于软期限；延迟事件循环下 renew 与 decide 均显式检查硬截止，不依赖定时器及时触发。
- 存储与发布都使用隔离快照，投影或调用者修改不会重定向内部绑定。先登记后发布，支持同步答复；外部发布异常不自动批准，错误不带原始私密详情。
- 每个审批 ID 在协调器进程生命周期内只能使用一次，避免关闭后重开同 ID 接受旧答复。消费历史仅保留 ID，实例释放时回收；不把等待状态恢复成跨进程执行许可。
- 提供按归属取消及幂等 dispose；私密认证、未决锁与模型会话均不由此组件接管。

## 测试与结果

新增 Application 测试覆盖同步受理、重复/重用、投影突变、软提醒、续期、延迟硬截止、事件失败、错误答复、按任务取消、释放、无效期限和续期。保留真实 Worker RPC 的原有审批生命周期回归，不通过删除旧断言掩盖变化。

局部任务 `b4e5e285b` 退出 0：5 文件 / 46 项通过、无跳过，耗时 5.80 秒；类型检查通过。包含新增15项、原审批生命周期、真实 Worker RPC、TaskApproval 投影和 OperationCommitClient 持久提交回执。

扩展任务 `bdf591515` 退出 0：140 文件通过、2 文件既有环境跳过；938 项通过、2 项跳过、0 失败，耗时 230.95 秒。类型、修改文件 ESLint、依赖边界（851 模块 / 3539 依赖）、行数、测试布局及差异检查通过。跳过项为未提供显式 opt-in 环境的 Agent/真实 SSH 集成，不能算真机证据。

## G1 尚余事项

1. **协调器自身不占执行槽，但当前调用它的 OperationScheduler pipeline 在等待审批时仍占槽。** 本批只是迁移唯一权威，没有宣称整个链路已释放槽；后续需可取消的释放/重新准入，并在排队后重做授权复核，不能简单移除串行保护。
2. 单一派发许可、代次撤销与 Main 耐久回执已存在的部分须继续统一契约验收；本批不保证远端 exactly-once。
3. 原生可信未启动证据仍未建立，保持 G1-A 的保守分类，不能由审批迁移重新开放自动 su 回退。
4. 暂不恢复旧审批等待；Worker 丢失或重启后需新提案/新绑定。整体 Main/Worker 丢失恢复还需单独证据。

只用本地测试、合成数据；未连接真实主机、未调用付费模型、未提交/推送。
