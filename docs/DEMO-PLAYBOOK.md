# 演示预案（40 分钟）

> 目标：演示不出意外。每个环节都写明「正常结果」和「失败时的台词 + 动作」。
> 演示前务必先读第 0 节的彩排检查。

## 0. 演示前彩排检查（开始前 10 分钟）

```bash
# 1. 启动（Windows / Git Bash）
sh start.sh
# 或 docker compose up

# 2. 确认后端活着
curl -s http://localhost:8000/api/health

# 3. 确认前端可开
#    浏览器打开 http://localhost:5173
```

检查清单：

| 检查项 | 期望 | 不满足时 |
| --- | --- | --- |
| 右上角状态 | 显示 `DEMO` 或 `LIVE` | 见 §6 降级方案 |
| 控制台 8 个按钮 | **可点击**（不是灰色） | 见 §6.1 |
| 日志区 | 有滚动日志 | 刷新页面 |
| 流量曲线 | 有曲线 | 刷新页面，检查 `/api/metrics` |
| 集群状态卡片 | 有 Pod 列表 | 见 §6.2 |

> 关键：**先确认 8 个按钮不是灰的**。曾经出现过 `:disabled="busy"` 空字符串被判为 true 导致全部按钮不可点的 bug，已修复并有回归测试，但彩排仍要肉眼确认一次。

## 2. 逐环节脚本

### 环节 3：一键部署

- **操作**：点「一键部署」
- **期望**：按钮变「执行中...」→ 成功提示 → 日志出现 `Deployment completed: release v3.N`（版本号 +1）
- **讲解词**：「滚动更新，不停服。版本号实时递增。」
- **失败台词**：「这里是演示后备模式，我继续走后面的容灾演练。」

### 环节 4：弹性扩容 + 压测

- **操作**：点「弹性扩容」→ 输入 `3` 或 `4` → **确认审批弹窗** → 点「压测演练」
- **期望**：弹出「审批高风险动作」→ 批准后 Pod 数量增加 → 新副本先以**黄色 `ContainerCreating` 启动中**（约 3 秒）
  → 随后转绿 `Running` → 指标卡同步变化（QPS 上升、响应时间下降）→ 流量曲线抬升
  → 日志 `Scaled guide-service to N replicas` 与 `Pod ... is Running`
- **讲解词**：「新副本不是瞬间就绪的 —— 黄色是启动中，三秒后转绿才真正可用。」
  这正好解释了为什么弹性伸缩需要时间。
- **讲解要点**：**扩容被后端强制审批**是真实现象，不是动画 —— 展示"变更必须确认"
- **失败台词**：「扩容请求走了审批流，我们直接看压测曲线。」

### 环节 5：混沌工程 / 容灾 ⭐

- **操作**：点「故障注入」→ 二次确认 → **再批准一次**
- **期望**：两次确认 → 日志 `deleted ... self-healing started` → 该 Pod **变红**（`Terminating`）
  → **约 5 秒后自动恢复绿色**（`Running`，restarts +1）→ 日志 `Self-healing complete`
- **讲解词**：「故意杀掉一个节点，看系统自愈。**注意这里有两道确认** —— 这正是防 AI 误操作的护栏。」
- **节奏提醒**：变红后默数约 5 秒就会变绿，别跳过这个瞬间 —— 这是本环节的戏点。
- **失败台词**：「目标 Pod 不在允许范围内，被安全策略拦下了 —— 这也是我们想演示的防护能力。」

### 环节 6：一键回滚 ⭐

- **操作**：点「一键回滚」
- **期望**：日志 `Rollback completed: v3.N -> v3.N-1`，版本号回退
- **讲解词**：「从发现问题到回滚完成，全程十几秒。」
- **注意**：回滚是**演示动作**（`mode: demo`），提示会显示「演示执行完成」。**不要**说成真实 K8s 回滚。

### 环节 7：故障排查 ⭐

- **操作**：点「故障排查」→ 看日志区
- **期望**：日志 `Diagnostics completed (live|demo): ...`
- **讲解词**：「不是只点按钮，而是看日志 → 定位 → 处理。」
- **加分**：直接在 AI 助手问「当前系统有什么瓶颈？」

### 环节 8：AI 更新 + 防幻觉

- **操作**：点「更新 AI 服务」→ 审批 → 然后在 AI 助手问「系统健康度如何」
- **期望**：镜像更新需审批；AI 回答**带数据来源标注**，如 `（演示数据）` / `（实时集群数据）`
- **讲解词**：「AI 不会编数据 —— 读不到指标时它会直接说'无法读取'，而不是给你一个假数字。**这是防幻觉的关键设计。**」
- **失败台词**：「正好演示一下：没有数据源时 AI 会拒绝给结论。」

### 环节 9：熔断 / 降级 ⭐

- **操作**：点「熔断降级」
- **期望**：日志 `AI service circuit opened; guide service switched to local cache`，3.5 秒后自动恢复
- **讲解词**：「一个服务挂了不拖垮全局，用户无感知。」
- **注意**：同样标注为演示动作。

### 环节 10：全端联调

- **操作**：点「全端联调」
- **期望**：日志逐条输出每个被管服务的状态（`Integration <service>: n/m ready`），
  末尾汇总 `全端联调通过：4/4 个服务已连通`
- **讲解词**：「这不只是看单个 Pod，而是一次端到端确认 —— 四个业务服务
  （导览、AI、大屏、小程序）是否都有就绪副本；live 模式下还会校验 Service 对象是否存在，
  因为只有 Pod 没有 Service 的话流量根本没有入口。」
- **加分演法**：先杀掉某个服务的全部副本，再点「全端联调」，
  它会准确指出 `✗ miniapp-api 0/1 ready failed=['ready']` —— 证明联调是真在检查而不是写死通过。

## 3. AI 演示问题清单（现场可临场问）

| 提问 | 预期回答 |
| --- | --- |
| 系统健康度如何？ | 带数据来源标注的健康度 |
| 当前有什么瓶颈？ | 建议扩容 4 副本 + **审批按钮** |
| 生成运维报告 | 结构化摘要 + 来源标注 |
| 帮我直接删掉一个 Pod | **被安全策略拦截**（critical） |
| （断网/关集群后）健康度如何？ | **明确说无法读取**，不给假数据 |

第 4 条是安全演示的核心：**AI 不能直接执行破坏性操作**。

## 4. 高危动作安全闭环（讲解要点）

三类动作必须人工审批：`扩容` / `删除 Pod` / `AI 镜像更新`。

审批链路的证据可现场调取：

```bash
curl -s http://localhost:8000/api/audit
```

每条记录包含：`action_type`（动作类型）、`target`（目标）、`risk`（风险等级）、
`decision`（pending / approved / rejected / executed）、`operator`（操作者）、`timestamp`。

> 说明：本 MVP 不含登录体系，`operator` 由调用方自报，默认 `control-panel`。

## 5. 模拟与真实的边界（务必如实陈述）

| 真实执行（live 模式下走 K8s API） | 演示动作（始终 demo） |
| --- | --- |
| 读取 Pod 列表 | 压测 |
| 扩容 | 回滚 |
| 删除 Pod | 熔断 / 降级 |
| Pod 自愈（5 秒恢复，restarts +1） | **指标数值**（见下） |
| 发布（写 release annotation） | CI/CD 状态（页面标 `DEMO 模拟`） |
| 镜像更新 |  |

**关于指标**：`demo` 模式下的 QPS / 响应时间 / 错误率 / 流量曲线是**合成的，但对扩容有真实响应**——
扩容后 QPS 上升、延迟与错误率下降（每个副本贡献 48 QPS，大于抖动幅度，方向稳定）。
这样“扩容 → 曲线变化”的演示是连贯的，但它**仍然是 demo 数据**，页面上会标注。
live 模式下这些值全部来自 Prometheus，不做任何合成。

**如果评委追问「这是真的吗」——如实回答当前模式。**
界面右上角与操作提示都会标注 `LIVE` / `DEMO`，这是刻意设计，不要含糊过去。

## 6. 降级方案（出问题怎么办）

### 6.1 按钮是灰的（点不动）

1. 按 `F12` 看 Console 是否有报错
2. 硬刷新：`Ctrl + Shift + R`
3. 仍不行 → 直接用 API 演示：

```bash
curl -X POST http://localhost:8000/api/deploy
curl -X POST http://localhost:8000/api/scale -H 'Content-Type: application/json' \
     -d '{"deployment":"guide-service","replicas":3}'
```

### 6.2 没有 Pod / 没有集群

1. 确认右上角是 `DEMO`（演示后备已开）
2. 若显示 `LIVE` 但列表为空 → 点右上角切回演示后备
3. 接口层面开关：

```bash
curl -X PUT http://localhost:8000/api/settings \
     -H 'Content-Type: application/json' -d '{"demo_fallback":true}'
```

### 6.3 后端挂了

```bash
# 单独重启后端
cd backend && python -m uvicorn app.main:app --port 8000
```

### 6.4 网络/依赖装不上

`start.sh` 需要联网装依赖。若现场网络受限，**提前**在有网环境执行过一次
`pip install -r backend/requirements.txt` 与 `npm install`（在 `frontend/` 内），
之后即可离线启动。

### 6.5 最后兜底：全静态演示

若程序完全起不来，用已存档的界面截图 `docs/screenshot-dashboard.png` 讲解
架构与安全设计，并把重点放在**设计思路**（审批护栏、防幻觉、模拟/真实分离）而非实时操作。

## 7. 一句话总结

核心链路是「部署 → 扩容 → 容灾 → AI → 联调」，
加分项是「**回滚、排障、熔断**」，
安全主线是「**高危必审批、AI 不编数据、模拟与真实不混淆**」。
