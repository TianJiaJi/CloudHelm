# Agent 重构 G1-A · 认证诊断证据收紧

> **状态：G1-A 保守分类修复与局部验证完成。** 承接 [G0 报告](AGENT_REFACTOR_G0_REPORT.md) 的认证证据阻塞；不是 G1 全阶段完成，不是可信原生启动证明或真机验收。未连接真实服务器，未调用付费模型，未提交或推送。

## 1. 本批目的与选择

G0 证明普通业务输出可以穿过生产 PTY 解析器，触发 `not-started/effects:none` 分类。风险包括将可能部分生效的变更错误地允许 su 回退或失去未决写锁。

本批采用保守支持范围，而不是声称已经找到全平台可信认证/启动协议：

- 混合 PTY/stderr 的拒绝、工具缺失或提示重复，仅作 `output-inference`。
- 业务是否启动记 `unknown`、影响记 `possible`、后续为 `verify`。
- 不能据此自动换身份、重放业务或清锁；真实有副作用的不确定项继续锁写。
- 确实没有派发业务（缺通道、客户端取消密码后尚未调用远端）仍保留原有 `not-dispatched/effects:none`。
- 真实退出码仍保留，`failed + businessCommand:unknown` 不冒充“远端进程仍在运行”；启动证据和最终退出是两种事实。

这会使某些真实 sudo/su 授权失败更保守，而不是更流畅；后续连续性改造需允许只读核验，不能为减少暂停恢复错误的零副作用声明。

## 2. 生产修改范围

| 文件 | 变化 |
|---|---|
| `packages/adapters/src/ssh-command-terminal.ts` | 删除仅凭 exit 125/127、提示标记、sudo/su 文本即宣称未启动/无影响的捷径；非零诊断改为未确认推断 |
| `packages/adapters/src/native-session-terminal.ts` | 旧显式 sudo 会话的 stderr 诊断同样保守；可疑信息可清除内存缓存，但不证明业务没执行；exit 0 不被诊断文本改成失败 |
| `packages/adapters/src/native-ssh-pty.ts` | 注明诊断标志源自混合文本，不是可信启动证据；不改变凭据开窗或放宽注入条件 |
| `packages/core/src/privilege.ts` | 输出推断的 sudo 不可用提示不再称“执行通道确认” |

未改变风险档位、硬禁令、用户保护路径、身份确认、凭据投递、审批许可或 `canOfferSuFallback` 的严格条件；没有新增工具或远端组件。`canOfferSuFallback` 仍要求可信 transport + 未启动 + 无副作用；本批诊断不再满足这些前提。

## 5. 剩余限制与下一步

1. **没有新增可信的业务启动/未启动证据。** 若要重新开放真实拒绝后的自动 su 提议，须单独证明来源隔离和支持范围；普通 nonce/标记/退出码/正则不足。
2. 受控 PTY 认证窗口的整体威胁模型、su 登录初始化副作用、旧显式 sudo 会话凭据载体不在本批重设计范围。保守结果分类不等于凭据通道已完成全面审计或真机认证。
3. 当前 TaskRunner 在部分结果下仍会整轮暂停。下一批拆分任务停止、写入阻断、认证取消与只读核验；不可直接删除安全阻断以追求连续性。
4. 未决写锁的自动核验/解除、用户接受风险并继续、审批与单一派发仍需 G1/G2 分批完成。
5. 历史已存的 `source=transport/not-started` 不自动回写或删除；本批改变新执行结果。旧审计、旧结果恢复和可能已被清除的锁不能凭新规则事后制造证据，迁移策略须另过门。

## 6. 本批退出结论

完成的是错误事实降级及防错误回退/丢锁回归，不是“自动 su 已可靠”或“Agent 连续性已改善”。保守新结果已具备后续编排使用的边界：只读诊断可执行，相关写入继续受未决锁保护；当前 TaskRunner 的整轮 abort 仍须下一批拆分。

继续保留原生可信启动支持范围阻塞。下一批优先处理 G0-C02/C03，将“用户拒绝的具体意图”“需要核验的写入”和“用户明确停止任务”分开；保留同批防绕过及所有派发硬门，不把风险未知一律改成无副作用。
