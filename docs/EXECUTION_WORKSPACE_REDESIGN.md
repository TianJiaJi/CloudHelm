## 用户目标

同一对话应能连续安排任务并共享操作事实，优先复用空闲终端，必要时创建多个终端。例如 A 启动持续服务后，B 检查接口；A 已开放的端口不应在 B 无故重复添加。不要求继承任意 `source`、Shell 函数或秘密环境变量。

## 核心范围

1. 修复数值输入清空后补零；保存 API Key 后显示固定圆点及已保存状态（不回填密钥）；思考内容只保留一层展开。
2. 同步升级 `pi-coding-agent`、`pi-agent-core`、`pi-ai`，候选精确版本为官方稳定版 1.5.0。兼容通过前不得宣称升级完成。
3. 有界只读识别主机 OS、发行版、版本、架构、内核、登录用户/UID/目录及基础工具，绑定连接代次与采集时间。未知不猜测，不为探测提权，不读取秘密；预估上下文和离线聊天不能打开网络连接。
4. 对话共享可检索的操作事实与证据；历史操作、一次观察和当前事实明确区分。旧记录不能作为无限时幂等凭证，也不能通过相同命令字符串机械禁止合理的新任务。
5. 同一对话按主机、身份和连接代次管理多个 AI 终端，优先复用空闲终端，有界按需分配。人工接管后不自动抢回控制权。
6. 普通执行和后台执行有独立任务标识，支持状态、增量日志、停止请求/退出确认、断线核验。回答结束不等于后台进程结束；长期生产服务优先使用适当的服务管理器。
7. 区分当前任务调整（steer）和后续任务（followUp），停止独立；排队消息不能提前覆盖当前执行意图。取消、过期和投递失败有明确状态。
8. 后台事件先更新后端与界面，再作为来源明确的数据进入后续上下文。默认不因每条日志或状态变化调用模型，不自动重启；明确授权的后续处理也必须重新核验范围和预算。
9. 结构化工具结果、授权范围内按需工具搜索、只读查询与汇总 Codemode。
10. 深接 SDK 上下文、压缩、进度/父子调用/结束事件及预算；原始历史和后端操作事实保持权威，不靠模型摘要解除风险。
11. 完成界面、升级/旧会话恢复、安全、队列、并发、后台任务/断线、构建与原生桌面回归，并提供隔离数据预览。

## 层次与权威来源

- Core：执行会话、任务、主机事实、状态转换和端口；不依赖 Pi/Electron/SSH。
- Application：终端池、任务生命周期、冲突调度、SafetyGate 和事实检索协调。
- Adapters：Pi 会话与工具翻译、SSH 控制协议、日志与 SQLite 存储。
- Desktop 装配与 utility worker：凭据/IPC/连接和运行态装配；Renderer 只投影状态。
- Pi 管理模型会话，不是远端进程管理器。会话历史不是远端任务状态数据库。
- 模型可申请选择终端，后端决定所有权、身份、容量、冲突和允许的操作。

## 运行语义

- 终端与执行任务分别建模：一个终端可以顺序执行多个任务；占用中的终端不接受新的普通命令输入。
- 后台任务至少区分启动中、运行中、已退出、失败、停止请求中和结果未知。进程运行并不证明健康检查成功。
- `stop` 发出信号不能立即标记已停止；断线也不等于进程退出。先核验原任务，不盲目重放。
- 新终端、新连接、新轮次不能绕过未决操作锁、身份绑定和审批。
- 多终端不等于无约束并发变更：相关或无法可靠判定独立的修改保守串行/阻止；持续服务旁的独立诊断可按策略安排。
- 关闭终端、结束对话、关闭窗口和退出软件应分别说明对任务的影响，不擅自终止或声称服务已持久化。
- 主机环境和工作目录变更有来源/时间/代次；不以人工界面上的 cwd 覆盖 Agent 审批绑定。
- 所有秘密在进入模型上下文之前隔离。`context_edit` 不删除原始历史，不能用于事后秘密清理。

## Pi 1.5.0 接入约束

- 三个直接 Pi 依赖固定同一版本，锁文件一并更新，保留已有 iconv-lite 固定补丁。
- 1.5 使用 pi-schema 校验并转换参数；必须在业务边界严格校验原始及执行参数，审核与最终操作一致，不依赖 SDK 隐式转换放行。
- TypeBox 的 Refine/Codec/自定义 Format 等不是新版工具校验保障；检查具体使用点，不机械替换所有项目契约。
- Azure provider 名称变更和 API 协议标识是不同概念；不全局替换、不默换供应商、账户或凭据。
- 新版压缩输出上限与 reserveTokens 语义不同，摘要与辅助请求也须预算预留、取消和目的绑定；禁止通过 SDK 自动重试重放业务工具。
- 优先官方上下文与生命周期钩子；`agent_settled` 仅表示模型停止自动继续，不能覆盖后台任务状态。
- 修改、启动/停止、提权、澄清等工具使用 `model-only` 阻止脚本嵌套调用。查询按需 `deferred` 或直接暴露，授权在执行时再次检查。
- Codemode 工厂显式 `models: false`；脚本仅能调用允许的查询，不能借模型入口绕过预算。`store/load` 仅作小型非秘密游标/引用缓存，不是权威任务状态。
- 嵌套调用经过后端审核/审计；SDK bounded nestedCalls 不含完整结果，不能替代本地操作记录。
- 工具 annotations 是未验证提示，不能替代确定性 SafetyGate 策略。
- 保持 SDK 资源与凭据隔离；不默认扫描全局 Pi 配置、加载任意扩展、启用 MCP、本机 Shell 或外传遥测。

## 界面

- 终端标签显示用途、状态和占用任务；新输出不抢焦点。
- 操作卡片标明终端/任务，提供增量日志及明确停止反馈。
- 已完成过程可以折叠；运行任务、待批准/澄清、恢复和未知结果始终可见。
- 消息区区分当前调整/后续排队，能看到待投递消息及取消状态。
- 模型生成、工具执行、等待用户与后台运行状态独立表达。模型费用区分供应商报告与估算，未知不当作零。

## 关键验收场景

- 清空端口保持空，测试/保存不得提交空值或使用旧端口；输入 2222 不出现多余零；合法 0 值（关闭心跳）保留。
- API Key 保存后输入值清空且有已保存占位；再次保存不能提交圆点字符串或回读旧密钥。
- 思考区域只有一层展开且不杜撰未返回的内容。
- 连续普通任务复用终端；A 长运行服务时 B 能做诊断，不向 A 的前台 stdin 注入新命令。
- B 能查询 A 的变更记录，不为补充输出或结论重放业务操作。
- 多轮压缩后重要事实仍可检索；恢复旧会话不发请求、不重放工具。
- 停止、超时、断线、人工接管和迟到回调不能覆盖新代次或错误标记任务成功/停止。
- 调整与后续排队分别生效；取消消息不会在恢复后自动投递。
- Codemode 不能调用修改/提权/额外模型；嵌套只读调用有边界、计量和审计。
- 新终端、工具发现和后台回调均不能绕过授权、审批、预算及未知结果写锁。

## 队列接入实现与阶段验收

- 1.5.0 的 `AgentSession.queue_update` 仅提供字符串数组；消费时用 `indexOf(messageText)` 删除，不能作为重复同文消息的权威 ID 回执。现有 `PiSession.pendingDocuments` 单 FIFO 也不能覆盖 steer／followUp 的不同优先级。
- 原生 Core Agent 提供 `steer(AgentMessage)`／`followUp(AgentMessage)`、分别清空队列及 `peekQueuedMessages()`；原生 custom message 保留 `details` 并产生消息事件。现已用后端 ID／实例 nonce 关联原生消息，保留一个已装入原生队列的槽位，并用后端状态区分待投递和已选择；同文消息不互相覆盖，不从用户正文推导身份，不使用 SDK 私有成员。
- 原生会话在消息开始时通知订阅方，在消息结束事件分发后追加历史；不能把任意 UI 事件或仅成功入队当成模型已经处理。投递记录与意图切换须在下一次请求的授权／预算关口前完成。
- 单条取消不能盲目清空后自动重发整个队列；须处理已被消费但事件尚未到达的竞态，恢复不重新投递取消／过期项。原始历史保留，取消回执不能伪造“撤回已处理的消息”。
- 入队时的上下文修订会随当前轮变化；实际投递须重新检查容量、授权／账户／策略绑定和预算，不因队列存在就悄悄重做摘要、重连主机或换用凭据。

- Main 使用版本 1 的 `conversation-inputs` 回执（通用 JSON 表，无 SQL 表结构变化）；Worker 在入队／实际选择／原生历史回执处等待持久化确认。恢复时待投递项过期，不连接、不请求模型、不重放。
- 取消、到期、暂停及模型切换会撤销尚未选择的消息；已选择项不能假称撤回。重复 ID 并发只装入一次，停止或授权变化发生在确认期间时不会再切换意图；历史回执提交失败的消息不进入后续正常请求上下文。
- 后台任务观察按任务／操作／连接／终端与进程代次、来源和观察时间进入后续事实索引；保持原有不自动唤醒模型的路径，停止信号送达与实际退出、健康状态分开。
- `bd9dd2ae6` 退出 0：14 文件／117 测试，以及类型、lint、依赖、行数、测试布局和 diff 门禁。之前 `baad1252a` 类型检查失败、`b3c04370f` 依赖循环失败、`b22a330c2` 七项兼容／fixture 失败均记录于 STATUS，未冒称通过。后续 `b612f9998` 全树 215 文件／2077 测试通过，7 文件／25 既有环境跳过，全部静态门禁通过。UI 和后续 SDK 功能仍未完成。
