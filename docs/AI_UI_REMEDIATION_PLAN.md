# AI 界面整改方案：以 Trae CN 为对标

> 状态：原UI审计方案保留，具体旧版实施范围以[当前整改总览](REPAIR_STATUS_OVERVIEW.md)为准。用户已确认F05/G01/G02、U06延期转新版；U05/U07及F06关联状态/报告部分一并移交，独立阅读、输入、键盘/IME和草稿功能保留。不按旧控制界面重复收尾，延期不算完成；下文原目标与历史证据保留。
>
> 本文补充[综合整改总表](PROJECT_REMEDIATION_SUMMARY.md)的 F03、F05、F06、G02 与 H02/H05。U01–U12 是 UI 专项工作包，不另计为 12 个独立漏洞，也不推翻总表的安全边界。

## 一、结论：不是换配色，而是重做 AI 阅读与交互层

当前 UI 已借鉴 Trae CN 的侧栏尺寸、灰阶配色、工具栏和思考披露条，但核心体验仍不完整：

1. **思考会流式更新，普通回答正文却等整条消息结束才出现。** 用户看到“正在生成”并不意味着能读到正在生成的答案。
2. **Markdown 只是安全基础渲染，还没有形成成熟的阅读组件。** 代码无语法高亮；正文、表格、代码的字号与空间不统一；长代码缺少阅读控制。
3. **诊断信息压过对话。** 没有活动时，执行工作区仍占据对话前方，并展示多个零计数/未知状态与说明。
4. **发送与停止挤在同一个按钮位置。** 运行中仍支持 Enter 补充，但没有可点击的补充发送按钮，操作发现性差。
5. **已有正确行为不能推倒重来。** AI 消息区已具备“上翻不抢滚动”；已有完成轮次折叠、成功工具摘要、安全链接、图片不自动联网等基础。

**目标：正常回答是主内容，思考与工具是次级过程，风险与待办是明确的操作入口；诊断细节按需查看。** 不把 CloudHelm 做成一个需要用户理解内部状态机的监控面板。

本次优先级修正：Markdown、代码块、阅读层级是首批体验工作，不再等全部后端重构完成后才做。涉及授权、输入路由、停止范围和风险解除的交互，仍必须与后端契约同步实施。

## 二、Trae CN 参考边界

- 使用仓库已有的 **Trae CN 3.4.9 / VSCode 1.107.1 IDE 侧栏**静态资料，不把国际版或 SOLO 全屏样式作为同一个目标。
- `.cache/trae-cn-ui-reference/styles.json` 留存样式来源、SHA-256 和选择范围。侧栏正文 tokens 包含 13px/20px；思考内容为次级 11px/16px；编辑区、发送键与工具栏有独立侧栏覆盖。
- `rea-summary.json` 对应的父记录为 `ev_5a487ed82dd486e12235e086237e01ee7b6f509e12e7c46d463b33e8fc199963`，只分析选定思考组件片段，不能证明完整 Markdown 实现、所有交互或当前运行时级联。
- 本轮没有启动/插桩 Trae，没有访问其真实聊天、登录态和服务；不宣称是最新版、逐像素复刻或功能完全对等。
- 学习布局、密度、披露和操作逻辑；CloudHelm 原创实现，不复制 Trae 打包源码、品牌资产、服务或遥测。

下文的代码折叠、输入交互和性能预算是 **CloudHelm 设计建议**，不是声称已经观察到 Trae 的所有相同行为。需要逐像素对齐时，另采同版本、同 DPI、同宽度、同主题的运行截图。

- 上述批准区仅在后端确有审批时出现；关键目标、影响和批准范围不能只藏在详情里。多个待办显示数量和逐项处理入口，不合并授权。
- 无需处理风险时不显示空警告/空工作区。执行中显示紧凑的当前活动与必要后台计数；详细请求、工具树、token、退出证据进入详情。
- 未知结果始终有可见提示、作用范围和处理入口，不能和普通成功过程一起折叠消失。
- 暂停模型、停止一个后台任务、停止整个会话分别命名。后端未提供某种能力时不画一个能点击却语义不实的按钮。
- 完成态优先回答；过程按轮次归组。按后端事实关联 operation/call，避免同一次动作在多个区域重复铺满。

## 六、技术实施原则

### 1. 正文流式先补契约，不在 renderer 伪造

- 复用现有会话与事件体系，不增加第二套执行状态机。Core 定义语义，adapters 封装 Pi；Desktop 负责跨进程装配；renderer 仅依赖 contracts。
- 进度至少绑定会话、运行/请求代次、消息身份、序号和状态；旧轮次、重复、乱序与会话切换不能串到当前回答。
- 适配层提取接口公开 text，不把 thinking、tool args、opaque signature 混入正文；发布前经过一致的脱敏边界。
- 临时增量与最终持久记录有明确接续规则。完成时替换/确认同一消息，不复制追加；中断不能自动标完成，也不能将暂存流当已持久证据。
- 允许合并 UI 更新，但不等待整条消息；已完成块尽量稳定。代码围栏、表格和链接尚未闭合时提供安全、可预测的临时显示，完成后收敛到同一最终 Markdown。
- 保留后端原文，不让 UI 为修复不完整语法而改写存储内容。流式重复解析和高亮的代价要实测。

### 2. 保留解析底座，升级组件职责

不因当前体验差就直接替换 react-markdown。现有 CommonMark/GFM、安全 URL、禁用原始 HTML 的基础可保留。源码缺口在组件与事件链，不是“这个库必然不能做好”。

建议拆分职责清晰的 Markdown 排版、代码块、高亮适配、消息操作和过程披露模块；避免继续往 `agent-panel.tsx` 堆叠全部逻辑。固定并验证新增依赖版本，检查体积、许可证、离线能力和长内容成本。

高亮器候选需先做小样和预算比较，不在本审计中虚构已经完成选型。默认只加载必要语言，未知语言和高亮异常安全退回原始文本；不 `eval`，不因为支持高亮而打开任意 HTML。

参考当前 react-markdown 官方文档：通过 `components` 或插件接入高亮，而不是默认附带高亮。文档经 Context7 核对，来源：<https://github.com/remarkjs/react-markdown#use-custom-components-syntax-highlight>。它不构成选择某一个高亮库的结论。

### 3. 视觉规格是待验收提案，不是硬套 Trae 所有数值

- 普通正文先以 13px/20px 作为紧凑侧栏基线，并支持用户缩放/更舒适的字号；中文字体回退和混排实测。
- 代码/表格先以至少 12px 的可读样例评估，不固定小于正文两级。标题依靠字号、字重和间距形成层级，h4–h6 不再单独锁死 12px。
- 使用少量间距和表面 tokens；只有代码、用户输入、必要操作区需要明显容器，普通回答不再额外套一层重卡片。
- 工具状态和时间是次级信息；命令、错误与待操作内容不是可牺牲的“小字”。关键交互满足清晰焦点与合理点击区。
- 先改善真实内容密度，不靠全局放大/缩小、增加动画或更多图标解决结构问题。

### 4. 不以美观为由解除安全限制

- 图片保持不自动联网；若未来增加预览，单独设计明确加载、URL/来源、网络隐私和失败策略。
- 文件路径不能直接变成任意 `file://` 或 Shell 链接；证据跳转走受验证的结构化引用。
- 代码复制只复制；“应用”“运行”若新增，必须形成新的后端操作并经过原有 SafetyGate。
- 图表/数学不是本轮核心缺口；按需求独立评估，不为追求格式数量引入脚本执行、外链加载和重渲染负担。
- 后端状态为唯一权威；有风险时保留显眼提示，但不必常驻全部技术解释。

## 七、落地顺序

### UI 阶段 0：冻结样例与目标行为

先将本轮有效反例转入正式回归，定义流式身份/结束接续与截图样例。保留旧版运行基线。当前缓存探针断言的是错误行为，不能原样当修复完成标准。

### UI 阶段 1：可独立交付的阅读改造

U02–U05、U08、U10；U07 中不改变后端语义的布局也可同时落地。交付真实 Markdown 混排、代码高亮与长块阅读、无空诊断面板的完成态。无需等待所有 SSH/数据库重构结束。

### UI 阶段 2：正文流式与交互契约

U01、U11 一起做，U06/U07 跟随输入队列和执行控制能力。不得先把全量快照频率提高来“做出流式”，也不得用前端猜测停止范围。

### UI 阶段 3：真实桌面验收与收口

U09、U12 贯穿所有阶段，最后完成 Electron、真实合成分块/中断链、DPI、长历史性能和三条业务链的验收。不是只挑一张欢迎页截图宣布对齐完成。

## 八、验收矩阵

| 维度 | 必测场景 |

| Markdown | 中文/英文混排，h1–h6，多段落，嵌套有序/无序列表，引用，任务列表，长 URL，代码内 HTML 字面量，宽表格和空单元格 |

| 流式 | 同一最终文本不同分块；前缀含未闭合代码/链接/表格；正常结束、中断、错误、旧轮次迟到、重复事件、最终归并 |
| 安全 | 原始 HTML/XSS、危险 URL、凭据型 URL、远端图片零自动请求、secret 分块、工具参数不混入正文、复制不执行 |
| 输入 | 中文输入法 Enter、Shift+Enter、多行与长粘贴、引用移动/撤销、鼠标发送补充、排队、取消准备、失败草稿保留、会话切换 |
| 状态 | 无活动、生成正文、思考、远端运行、等待批准、私密认证、未知结果、后台待关注、模型已停但远端未停 |
| 阅读 | 手动上翻、文本选择、代码展开、窗口宽度变化、最终折叠归并、历史加载、回到最新；审批出现不得无条件抢焦点 |
| 布局 | 深/浅主题，330/420/620px 侧栏，640/900px 高度，100%/125%/150% DPI 或缩放，键盘操作和 reduced-motion |
| 性能 | 多会话长历史、活动消息长输出、高亮语言加载；记录首段到达→可见、IPC 字节、长任务、输入响应和内存 |

建议先采用的性能目标：受控桌面测试中，**安全正文已到 adapter 后到界面可见的 P95 不超过 200ms**；不是从用户发送起算，也不把模型思考、审核或网络耗时算作 UI 延迟。这个目标尚未实测达成，需写明硬件/样例并依据基线校准。已完成的其他会话不因每次正文增量反复搬运/解析。

人工验收问题只有几个：能否先看懂回答？能否看懂正在等什么？能否自然发送下一句？是否能读长代码而不迷路？是否知道停止会影响谁？真实风险是否仍然清楚？
