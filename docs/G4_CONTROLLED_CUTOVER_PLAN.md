# G4 开发任务书：受控切换与兼容验收

**状态：待开发。** 前置：[v5.3 实施计划](V5_3_REFACTOR_PLAN.md) · [阶段进度](AGENT_REFACTOR_PROGRESS.md) · [G3 真机验收](G3_PUBLISH_ACCEPTANCE_REPORT.md)。

## 1. 交付目标

让升级后的历史与未决状态仍可理解、可核验；每个可写会话在任意时刻只有一个后端执行权威。升级、断线、崩溃或版本不兼容都不得导致重复派发、审批继承或风险锁丢失。**G4 验收的是切换安全，不是重写任务运行时，也不是生产发布批准。**

### 开发边界

- G3 已覆盖隔离环境中的真实部署与 `su` 认证窗口断线，不代表真实文件提交中途已经验证，也不证明模型请求数改进。G4 不重做 G3 功能演示。
- G3 留下的发布守卫错误处理、提交前强制哈希检查继续登记为后续加固，不阻塞本轮离线切换验证；未加固的发布路径不能借 G4 进入客户或生产环境。不要为了切换而降低 `SafetyGate`、认证或恢复约束。
- 不做 G5 的工具/人工终端归并，不做 G6 扩展；不重写 SSH、凭据或 SQLite。默认使用本地副本、合成数据和可故障注入 transport，不调用付费模型或真实业务主机。

## 2. 开发顺序与产物

### G4-A · 盘点真实读写入口与兼容边界

1. 固定改动前 HEAD、G0 旧基线 `5b66d92` 与已有的其他受支持升级源版本。实际使用旧版本生成脱敏或合成的数据库、Pi 会话文件及对应版本清单；不要只用新结构模拟旧数据。保留校验摘要和生成方式。
2. 从 Main 的启动、续跑、处置 IPC，沿 Worker `TaskRunner` / `ExecutionScheduler`、`OperationCommitClient` 到 `SafetyGate` 和传输派发，绘制调用链；同时核对 `SqliteStore`、`AppState`、`RecoveryDecisionStore` 和 Pi 会话存储的持久化职责。列出所有能发起新写入、释放锁、批准或恢复任务的入口，以及各自的唯一权威。点名当前仍可达的旧入口；如果已经只有一条路径，交付调用链和反证测试即可，不凭空增加版本路由或双运行时。
3. 给每种旧状态标注「可续跑」「只能只读」「需人工核验」，包括正常结束、等待审批/认证、已确认未交接、已交接但未收到结果、后台可能仍运行、风险处置已记录但续跑未确认。历史的 `answered`、`failed` 或缺字段不能被当作未决操作已结清的证明。

### G4-B · 兼容与恢复：先契约测试，再接实现

- 仅在确有 schema 变更时新增版本化迁移。迁移重启后可重复启动，不重复生成操作、回执或审批；失败则拒绝进入可写模式。涉及 SQLite 与 Pi 文件时不能假装跨介质原子：使用持久迁移进度及可恢复阶段，或在数据不齐时保持只读。核对历史可读、关联 ID 稳定，审计与未决账均不消失。
- 按会话绑定已核验的唯一写入路径；旧会话首次续跑前检查兼容性与未决账，不能把已有活动任务直接换实现。存在归属不明或不兼容的会话，保留历史与阻断，不自动启动或重试。策略/会话/连接代次变化时旧审批与启动许可失效；认证输入不跨重启恢复。
- 切换不替代恢复。已交接或无法确定交接的操作保持 `unknown`/可能副作用，保留相关主机风险域写锁；恢复只做授权的只读核验，处置后才可重新提出经独立审核的新操作。若无法证明未交接，禁止按未执行处理。处置记录已写而续跑结果未知时，不回滚处置，也不在重启时无条件唤醒任务。

### G4-C · 接管、删旧与停用预案

- 用本地故障注入完成兼容和切换矩阵后，只移除**已有替代且证实无业务调用方**的旧写入口。临时桥只翻译协议，不迁回第二审批权威、计时器或派发路径。合法人工终端与只读历史入口不在删除范围。
- 提供停用和恢复手册：先关闭新派发，保留审计与未决账，必要时只读打开历史；只有证明旧版本读写兼容且锁与审计完整，才允许回退可写。不能用恢复旧备份来抹去切换后已经发生的远端操作；不兼容用前向修复或只读，不做真实业务双写。

## 3. 验收矩阵

| 编号 | 怎么验 | 通过条件 |
|---|---|---|
| G4-01 历史兼容 | 从各受支持旧版本的数据库与 Pi 会话副本升级；重复启动；注入迁移中断及版本不兼容 | 聊天、操作、关联 ID、审计与风险处置可追溯；不重复迁移；失败显式只读或阻断，不能静默重建空库或丢失未决账 |
| G4-02 审批与鉴权 | 在等待审批/认证、审批后尚未交接时切换或重启；提交迟到/重复响应 | 旧响应、令牌和密码不能继续使用；未经当前代次复核的操作 **0 次派发**；缺失权威 ACK 不派发 |
| G4-03 单一写路径 | 对同一会话竞争发起启动、续跑、处置或连接重建；用 transport 记录真实交接次数 | 同一已授权操作最多一次交接；禁止旧新实现并行掌权；多窗口或重复 IPC 不能多派发 |
| G4-04 崩溃边界 | 分别在审计持久化/ACK 前后、交接前后、结果/风险处置持久化前后终止 Main 或 Worker，再启动；每例记录确切故障点 | 确证未交接的旧操作不自动启动；已交接或不明的 **0 次自动重发**；相关风险域锁仍在，先只读核验；迟到结果只能按原操作归账，不唤醒已停止任务 |
| G4-05 恢复与停用 | 让同风险域写入尝试重连、换任务或换身份；验证对账及明确人工处置；演练旧版本不兼容 | 写锁不被换路线绕过；恢复不把未知改成成功、不自动批准下一操作；不兼容回退不能进入可写，审计与未决状态保留 |
| G4-06 删旧与门禁 | 提交入口对照表、删除项及调用方证据；运行针对性回归、全量测试、typecheck、lint、依赖/行数/布局检查及生产构建 | 无活跃双写入口或旧写路径旁路，既有恢复行为无回退；记录通过、失败和跳过项，环境跳过不能充当通过证据 |

**证据口径：** 不只看 UI `answered` 或操作快照。每个故障样本保留脱敏的操作 ID、会话/连接代次、持久记录状态、ACK 边界、transport 交接次数与恢复结果。至少有一次先观测到 transport 交接再制造崩溃，而不是把认证窗口断线冒充业务交接。真实 SSH 若另行获准，只用于补充，不能替换可重复的故障注入矩阵。

## 4. 交付与结项

- 提交入口/权威对照表、兼容矩阵、迁移及停用手册、故障用例结果与准确的验证命令，并给出被测提交和未覆盖项。
- 按 A → B → C 小批交付，经验证后本地提交、简体中文提交信息；只暂存本批文件，不 push。未达门禁记为受阻，写清受影响状态与证据，不通过降级放行来结项。
- G4-01 至 G4-06 全部通过，才可在进度表标记 G4 完成并提出进入 G5。生产批准另行审查。
