# 受控文件编辑与显式恢复

本页描述开发实现，局部验证及真实平台验收结果以整改账为准。不连接真实主机或调用付费模型来自动证明可用。

## 使用闭环

1. `read_remote_file` 取得完整、未脱敏的 UTF-8 正文及 SHA-256。默认使用当前登录；需要 root 时显式传 `privilege=root`，由后端安全门审核并按实际需要申请私密认证。普通读取沿原有 SFTP 持久读取审计；root 读取使用独立固定驱动。
2. `prepare_remote_edit` 绑定源版本，做唯一字面替换并返回全部变更行的统一 diff。空源文件允许空 `oldText`。支持完整元数据的后端会签发任务本地 `editId`；不支持时只有 preview-only，没有提交能力。准备不生成远端暂存文件，不锁远端文件。
3. `apply_remote_edit(editId)` 消费一次令牌。安全门重新审核确切正文、diff、源版本、元数据摘要、主机/身份/目录、策略及终端代次。拒绝、取消、失效或未知结果后都不能复用令牌。
4. 固定驱动提交前复核执行 UID、内容和元数据版本，写同目录私有候选，保持 owner/group/mode/ACL/xattr，读回候选，复核原目标后以 `renameat2(RENAME_EXCHANGE)` 原子交换，核验目标与被交换版本并 fsync。成功收据说明这次观察，不等于服务健康或整项业务完成。
5. 可用 `check_remote_edit(recoveryId, validator)` 单独检查配置；`recoveryId` 是成功文件操作的 ID，validator 只接受 nginx、sshd、systemd-unit。分别调用固定路径的 nginx -t、sshd -t 或 systemd-analyze verify，不接受任意参数，不重启服务。验证器也经过独立审核/权限路由；不是任意配置或动态模块的无副作用沙箱。失败或未知影响仍遵循原有核验/人工处置机制，不自动放开主机写锁。
6. 用户明确要恢复时，`restore_remote_edit(recoveryId)` 从后端已确认成功的操作取收据，重新读取当前目标和私有原件，拒绝任何变化，生成逆向完整 diff，并进行一次新的精确审核和认证。原 inode/元数据通过交换恢复，刚替换的版本留在相同私有目录中，并产生新收据。恢复不是凭旧收据直接获权，不自动清除未知操作或回滚服务。
7. `discard_remote_edit(editId)` 只丢弃本地准备状态，无远端文件可清理。已提交的恢复目录不会由此删除。

## 能力边界

- 当前完整提交配置限定 Linux 本地 ext 系列/XFS、Python 标准库及固定 `/usr/bin/python3`、可用 xattr/flags/扩展 inode 元数据接口和原子交换。完整命名空间读取要求实际 UID 0 与 CAP_SYS_ADMIN；普通非 root 身份、受限容器、远端文件系统、缺少能力或辅助器时不签发提交令牌。已是 root 的 SSH 登录无需再 sudo；普通登录的显式 root 意图走已有可信 sudo/askpass 通道，不自动改为 root SSH/su。
- 单链接普通文件，路径逐层拒绝符号链接；源/结果最多 1 MiB，diff 64 KiB、32768 行，准备输出 96 KiB。任务最多四份准备/四份读取缓存，合计预算 8 MiB，令牌十分钟过期。缓存绑定任务/模型控制代次、主机/策略/登录、终端及连接授权上下文。
- 特殊权限位、非默认 inode/project/allocation 标志，以及 capability/IMA/EVM 完整性属性拒绝提交，不通过剥离属性、改身份或普通覆盖来降级。保持范围是已核验的 owner/group/mode/ACL/xattr 和支持的 flags，不承诺保留 inode 编号、mtime/ctime、稀疏布局或服务状态。
- 原子交换不是跨进程 CAS 或全局快照隔离。提交前冲突拒绝；交换窗口中的外部竞争、交换后校验/flush 失败、目录移动、断线或收据不明均保留 possible/unknown，不盲目交换回去覆盖外部写入。仍可能有原文件已打开的外部写句柄；恢复前必须再次证明备份未变。
- 恢复副本位于同目录 `.cloudhelm-edit-<uuid>/entry`，目录由实际执行身份拥有且模式 0700。保留以支持人工检查，不做未经审核的自动删除。若程序被强制结束，可能留下私有候选/恢复目录；先核验原操作与路径，不自动重放。生产环境生命周期/配额清理仍需明确策略，不能把丢弃本地预览当作远端清理。
- 密码仅进入当前操作绑定的可信认证接收方，不进入模型、普通 Shell 输入、启动参数或审计正文。正文/协议收据通过私密独立通道，审计只保存操作预览、有限结果和无正文恢复收据；已知疑似秘密内容不生成可编辑快照。
- 旧 SFTP `write_remote_file`/上传仍只支持新建。旧 `edit_remote_file` 停用，哈希/root 参数不能恢复旧覆盖路径。不得借 Shell 暂存安装、删除重建绕过这些限制。

## 验证范围

局部验证覆盖固定 Python 事务算法及实际 staging 方法的系统调用替身、私密协议、SafetyGate/执行器/工具闭环、版本竞争、取消与未知结果；原生 Pi/TaskRunner 使用本地模型和文件驱动替身。它们不等于真实 Linux 文件系统、ACL/LSM、sudo/PAM、SSH 断线、跨平台或安装包验收。最终/全量与隔离主机验收仍按原计划另行进行。
