# 受控文件编辑与显式恢复

本页描述开发实现，局部验证及真实平台验收结果以整改账为准。不连接真实主机或调用付费模型来自动证明可用。

## 使用闭环

1. `read_remote_file` 取得完整、未脱敏的 UTF-8 正文及 SHA-256。默认使用当前登录；需要 root 时显式传 `privilege=root`，由后端安全门审核。普通读取沿原有 SFTP 持久读取审计；root 读取经 root SSH 直连驱动执行。
2. `prepare_remote_edit` 绑定源版本，做唯一字面替换并返回全部变更行的统一 diff。空源文件允许空 `oldText`。支持完整元数据的后端会签发任务本地 `editId`；不支持时只有 preview-only，没有提交能力。准备不生成远端暂存文件，不锁远端文件。
3. `apply_remote_edit(editId)` 消费一次令牌。安全门重新审核确切正文、diff、源版本、元数据摘要、主机/身份/目录、策略及终端代次。拒绝、取消、失效或未知结果后都不能复用令牌。
4. 固定驱动先探测执行身份（字面 `id -u`，按连接代次缓存）与 SFTP 可用性。提交前复核执行 UID、源内容哈希与元数据摘要；在私有 0700 暂存目录写入候选并复制 owner/group/mode；以字面 `ln` 在同目录建立当前内容的硬链接备份，核验备份与目标未变后，以字面 `mv`（同目录 POSIX rename）原子发布，读回核验内容哈希与属性摘要，成功后移除暂存目录。成功收据说明这次观察，不等于服务健康或整项业务完成。
5. 可用 `check_remote_edit(recoveryId, validator)` 单独检查配置；`recoveryId` 是成功文件操作的 ID，validator 只接受 nginx、sshd、systemd-unit。分别调用固定路径的 nginx -t、sshd -t 或 systemd-analyze verify，不接受任意参数，不重启服务。验证器也经过独立审核/权限路由；不是任意配置或动态模块的无副作用沙箱。失败或未知影响仍遵循原有核验/人工处置机制，不自动放开主机写锁。
6. 用户明确要恢复时，`restore_remote_edit(recoveryId)` 从后端已确认成功的操作取收据，重新读取当前目标和私有原件，拒绝任何变化，生成逆向完整 diff，并进行一次新的精确审核和认证。提交前先为当前被替换版本建立硬链接备份并核验，再把原件 `mv` 回原位；原 inode 及其属性随重命名恢复，并产生新收据。恢复不是凭旧收据直接获权，不自动清除未知操作或回滚服务。
7. `discard_remote_edit(editId)` 只丢弃本地准备状态，无远端文件可清理。已提交的恢复备份不会由此删除。

## 能力边界

- 完整提交需要 SFTP 子系统。无 SFTP 的主机只保留字面 shell 只读检查路线（stat/sha256sum/head/ls/rm/rmdir），快照如实标注不可提交；apply/restore 在任何远端效果前拒绝，不降级为普通 Shell 写入。
- root 文件事务经 root SSH 直连执行；驱动以 `id -u` 复核实际 UID 必须为 0，否则拒绝。文件事务不再经 sudo/askpass 注入密码，普通登录不隐式提权。
- 单链接普通文件，路径逐层拒绝符号链接；源/结果最多 1 MiB，diff 64 KiB、32768 行，准备输出 96 KiB。任务最多四份准备/四份读取缓存，合计预算 8 MiB，令牌十分钟过期。缓存绑定任务/模型控制代次、主机/策略/登录、终端及连接授权上下文。
- 属性保持范围是已核验的 owner/group/mode（属性摘要）。SFTP 无法核验或复制 ACL/xattr，apply 不声称保留它们；需要保留 ACL/xattr 的文件应人工处理。restore 移回原 inode，随 inode 的属性自然保留。特殊权限位或非执行身份拥有的文件不签发提交令牌。
- 摘要是 v2 stat 字段摘要（size/mode/uid/gid/mtimeSec 与 owner/group/mode 两组），刻意不含 ACL/xattr/device/inode 承诺；旧 Python 驱动的 v1 摘要不跨格式比较，保守拒绝。
- 硬链接备份加同目录 rename 不是跨进程 CAS 或全局快照隔离。提交前冲突拒绝；发布窗口中的外部竞争、发布后读回不符、断线或收据不明均保留 possible/unknown，不盲目换回覆盖外部写入。仍可能有原文件已打开的外部写句柄；恢复前必须再次证明备份未变。
- 恢复备份是同目录 `<文件名>.cloudhelm-backup-<事务ID>` 硬链接，保留以支持人工检查与显式恢复，不做未经审核的自动删除。私有暂存目录 `.cloudhelm-edit-<事务ID>` 在提交成功后移除；异常中断可能留下暂存目录或备份，先核验原操作与路径，不自动重放。生产环境生命周期/配额清理仍需明确策略，不能把丢弃本地预览当作远端清理。
- 密码仅进入登录/凭据管理的可信接收方，不进入模型、普通 Shell 输入、启动参数或审计正文。文件命令均为固定字面量并走私密原生执行通道；审计只保存操作预览、有限结果和无正文恢复收据；已知疑似秘密内容不生成可编辑快照。
- 旧 SFTP `write_remote_file`/上传仍只支持新建。旧 `edit_remote_file` 停用，哈希/root 参数不能恢复旧覆盖路径。不得借 Shell 暂存安装、删除重建绕过这些限制。

## 验证范围

局部验证覆盖 SFTP 事务路线与 shell 降级路线的内存替身、字面命令注入边界、探测缓存与连接代次、SafetyGate/执行器/工具闭环、版本竞争、取消与未知结果；原生 Pi/TaskRunner 使用本地模型和文件驱动替身。它们不等于真实 Linux 文件系统、ACL/LSM、SSH/SFTP 断线、跨平台或安装包验收。最终/全量与隔离主机验收仍按原计划另行进行。
