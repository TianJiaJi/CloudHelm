# Agent 重构 G1-F · 原生前台 exec 的单次启动许可

> 状态：本批实现、全量自动回归及构建通过。基线本地提交 `aaca187`，分支 `refactor/agent-v5_3`。承接 [G1-E 执行器入口准入](AGENT_REFACTOR_G1_ENTRY_REPORT.md)，不宣称完成全执行面的最终派发契约。

## 覆盖的实际边界

对后端选择为 `native-exec` 的前台业务命令，SafetyGate 签发进程内 `claimStart` 回调，经 TerminalManager、SshCommandTerminal、SshTransport 传到 native SSH exec，在调用 `ssh2.client.exec` 前同步复核并单次消费。异步本地/远端预检不消费业务许可。

- 拒绝、过期、取消、策略/终端/控制代次失效或回调异常，不调用业务 `client.exec`，返回未派发。
- SshTransport 提供实际 hostId、命令原文和 cwd，Gate 同被审核的目标逐项匹配，防止把 A 的许可错误用于 B 的主机/命令/目录。
- 回调第一次调用即消费，成功或失败都不能再次使用；Gate 执行器尝试结束时也撤销未使用的许可，不允许结果返回后复活。
- 许可只限已绑定的提案和当前上下文，不进入模型、IPC、数据库或日志；新的尝试须经过新的 Gate/审计，不复用旧回调。
- 正常启动后不再检查启动时限；输出与真实退出仍受原持续上下文/停止规则约束，不因批准窗口过去伪造 unknown。
- 客户端已接收 exec 请求但分配失败、断线、信号或未观察退出，仍按可能已派发/未知处理，不假称 exactly-once，也不证明远端业务已经启动。

## 限定范围

本批仅覆盖普通原生前台 exec 的业务启动。固定系统探测不借业务许可；PTY 的 sudo/su、显式身份会话、后台启动/控制、结构化文件多步操作尚未接入同类单次消费，必须分别设计和验证。不要把 Core 可选字段理解成所有路线已经支持或模型可自己选择执行通道。

原生认证的可信启动/未启动证据仍未建立；本批不解除 G0 的该项支持范围阻塞。

## 测试与结果

1. 预检等待期间批准到期，业务 SSH exec 没有发生，返回未派发。
2. 同一许可第二次请求不能再次调用 SSH。
3. 返回的尝试不能在模拟时钟回退后复活许可。
4. 启动后时限过去仍保留实际输出及 exit 0。
