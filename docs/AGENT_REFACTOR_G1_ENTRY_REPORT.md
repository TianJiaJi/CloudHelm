## 要解决的边界

G1-D 已在审批恢复槽位后复核硬截止，但 Gate 交给主机执行器后仍可能等待其它主机操作。若仅检查持续有效的身份/终端/策略，已经过期的批准可能继续进入执行器；反之，把批准期限塞进运行中检查，又可能把正常长命令的真实退出误报未知。

本批分开两种回调：

- `canEnterExecutor`：内部执行器入口准入，含审批硬截止、review/control 和原上下文；排队后必须检查。
- `isAuthorized`：持续上下文约束，不仅因审批开始窗口过去而宣告运行中进程未知。

SafetyGate 提供这两个后端回调，不作为 IPC/模型参数。HostSerialExecutor 在取到主机队列后重新检查，异常也失败关闭；TerminalManager 在交给命令通道前再次检查，失效返回 `not-dispatched/effects:none`，不占 pending、不丢输入归属。未派发失败不制造未知写锁，后续合法操作仍可进入。

## 非承诺范围

**执行器入口不等于真实 SSH 交接点。** 底层驱动仍可能异步预检或准备，结构化文件有多步 IO；本批未声称已将时效或单次许可消费覆盖每一个实际副作用的交接边界。后续需单独端口与适配器契约，不把本回调当可序列化 bearer token，也不以一次 true 证明远端 exactly-once。

已发起的操作继续受原身份/连接/策略及停止约束；本批不开放新身份、不改变三档分级、不解除未决锁、不改变 G1-A 的保守认证事实。
