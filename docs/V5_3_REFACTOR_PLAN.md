## 1. 要解决什么

用户需要的是：任务下达后，Agent 能根据真实结果连续推进；普通失败会调查和调整，不因一项技术限制结束整轮；未知变更不盲目重放；必要的人类决定清楚且次数合理。

重构成功须同时满足：

1. 同条件业务对照下，成功率不降低，模型请求、可避免暂停和耗时显著改善。
2. 新增一种错误处理或主机适配时，修改集中在明确的业务用例或适配器；不需要同时修改提示词、UI 和连接层才能改变业务行为。
3. 凭据、人机隔离、派发复核、审计和未决写锁不退化。体验目标不能换取安全门绕过或减少业务验证。

**核心不是“更少工具”，而是：发生了什么、还允许做什么、谁决定下一步，三者一致。**

### 1.1 现版问题依据与应保资产

代码审计的定位入口（开工时复核，不依赖固定行号）：

| 入口 | 当前问题或应保能力 |
|---|---|
| `worker/execution-scheduler.ts`、`worker/task-runner.ts` | 部分失败把远端阻断、任务暂停和模型 abort 绑定；需拆开操作局部失败、写入锁与整轮停止。 |
| `worker/review-coordination.ts`、`worker/agent-prompt.ts` | 普通技术失败、审核拒绝、用户停止的后续路径仍易混淆；不能只改提示词。 |
| `worker/operation-feedback.ts` | 已有结构化结果，但与大段限制指导并存；应改为稳定事实和有限后续能力。 |
| `application/safety-gate.ts`、`application/host-serial-executor.ts` | 保留并复验统一审核、派发复核、跨任务主机风险域及未决阻断。 |
| `adapters/pi-session.ts`、原生 SSH 与 SQLite 适配 | 保留并复验会话、压缩、受控工具、连接代次、持久化及恢复，不重建已有可靠轮子。 |

本轮不再笼统声称“全是执行模型缺陷，与代码无关”。语义、编排、提示词与权限呈现均须由契约测试检验。

## 2. 已采纳的方向与替代裁决

| 事项 | 本轮基线 |
|---|---|
| 重写范围 | 重建 Agent 编排、工具契约、结果归约与恢复；沿用四个包和 Electron 进程结构。已验证底座可经复审复用，不要求为了重写而抄写一遍。 |
| 首版 | 单主机、原生 SSH、逐操作、操作级身份。逻辑作用域从第一天包含任务和主机，不提前开放多主机授权。 |
| 安全接入 | 首个有副作用的测试切片即接最小 SafetyGate、审计和派发复核；不是最后一阶段补安全。 |
| 连续性 | 阻止某项操作或相关写入，不自动等于终止模型；普通失败允许在边界内调查、调整。明确用户停止必须终止续跑。 |
| 状态 | 后端是权威；模型可持有作业/操作查询引用，不能用记忆决定作业活性、授权或解锁。 |
| 会话 | 保存显式默认 cwd 与已授权非秘密环境配置；不继承任意 `cd/export/source`、函数、别名或人工 Shell 状态。 |
| 权限 | 操作风险、身份、认证、信息披露、未决写入分别控制。三模式只改变操作裁决路由，不关闭其它门。 |
| 模式二 | 同模型重提是“显式自审”，不是独立安全审核；自动裁决必须符合用户委派范围和可机械核对的绑定，不承诺识别模型是否真的拿得准。 |
| 模式三 | 用户预授权范围内自动派发；不虚构模型事前审理。越界不执行，硬门仍有效；认证和风险承担不是执行类询问。 |
| Pi | 保留经验证的模型会话、压缩和生命周期；关闭未经自有授权入口的文件、Shell、Skills、MCP 等独立 IO。不是把 SDK 削成 HTTP 请求库。 |
| 人工终端 | 不走 AI 三档执行裁决，但仍核对主机信任、登录、接收方和隐私；记录可观察事件并标盲区，不承诺捕获所有按键或全部命令。 |
| 核验 | 核对派发内容、结构化目标及指定业务证据；不承诺观察任意程序对全机的全部影响。 |
| 扩展 | 五域后续收敛；Skills、受限知识 MCP、多主机、子代理按序推进。Go 与对外 MCP 为另行立项候选，不挡首版。 |

## 3. 连续性：必须实现的行为

以下为验收需求，不是提示词建议。后端返回事实与当前允许的动作；模型决定业务方案，后端重新校验每次调用。

| 事件 | 当前操作与任务应如何继续 |
|---|---|
| 参数错误、命令形式不支持、已证实未派发 | 结束该提案，给出具体缺失能力；模型可修正参数或提出实质不同的受支持方案，无须点击“继续”。 |
| 工具缺失、业务失败，证实无副作用 | 不新建未决写锁；可调查并更换实现方法。缺少 python 不等于部署不可能。 |
| sudo 不可用/授权拒绝，可信证明业务未启动 | 可以提出受控 su；身份路径需用户确认，各新操作重新裁决。认证失败或文本相似不够作此证据。 |
| 用户拒绝某项操作 | 绑定被拒意图，不许换写法/身份/工具实现相同被拒效果；允许无关且已授权调查或讨论替代目标。范围不清则澄清，不自动扩大拒绝，也不绕过。 |
| 用户取消认证 | 关闭挑战，停止依赖该认证的执行，不再次自动索密或换身份；可解释或做不依赖该身份的已授权查询。 |
| 可能部分生效、结果未知 | 锁住相关主机风险域的后续写入；模型仍可做受控只读核验和恢复分析，不自动重放。核验受限、预算耗尽或确需用户决定时才进入相应等待。 |
| 用户明确停止任务 | 撤销本轮派发权、队列和交互；中断模型并尝试停止可控作业。迟到结果仅记账，不唤醒任务。 |
| 安全/审计基础设施故障 | 当前操作不派发；保留故障事实，允许安全的离线解释。不能为保持连续而降级放行或反复冲击故障入口。 |

请求预算、重复失败和无进展防护继续存在，但用“新证据/新方案/重复原尝试”区分进展；不以任意三次不同失败作为整轮终止条件。具体阈值在基线阶段确定并回归，不无限重试。

## 4. 首个交付切片与业务走查

### 4.1 正向：权限受限仍把服务部署做完

环境：获准的隔离 Linux，普通账户无本次操作的 sudo 授权，用户可在客户端通过受控 su 认证。选用确实提供健康端点的最小服务 fixture；不以 `sleep` 或仅 `active` 冒充应用健康。

1. 固定主机授权和任务，注入有来源的能力卡；不据未知 NOPASSWD 推断无法部署。
2. 通过用户选定的本地材料及结构化文件入口准备非秘密构建产物和配置。
3. 需要系统目录写入时显式请求 `root-required`；普通用户写 `/etc` 也必须处理权限，不能到写 systemd 单元时才发现。
4. sudo 仅在可信未启动证据下提出 su 路径选择；用户确认不等于批准业务命令，也不缓存 su 密码。
5. 每项文件发布、配置校验、单元加载/启用/启动分别按实际风险裁决并复核。不得暗含一次批准覆盖整段部署。
6. 核对目标内容、配置语法、服务状态与应用健康端点；给出实际观察、访问方式、未知项及恢复办法。

**不承诺“只有第 5 步暂停一次”或“只输入一次密码”。** 必要裁决、身份选择和认证单列计数；不必要整轮暂停应消除。若原生路径无法证明阶段或安全完成某项文件提交，在阶段报告中列为阻塞，不用脚本包装假装解决。

### 4.2 故障：已交接后失联

注入派发后断线或可能部分生效：保留原尝试 → 阻止相关写入 → 继续只读核验 → 证据足够则提交对账并解锁；不足才允许明确风险决定。用户可选择拒绝、仅接受并解除、接受此风险并继续。

“接受并继续”是一个幂等后端用例：持久确认、同步锁、检查其他阻断与用户停止状态，条件成立才让模型决定下一步；不重放原命令、不批准下一条命令，不把旧未知改成成功。仍有可信运行作业时不能借风险确认解锁。

## 5. 实施阶段与具名通过门

阶段号仅为顺序，不作为“可连接生产”的授权。每阶段先写契约测试，再改实现，提交简短完成报告。

| 阶段 / 通过门 | 工作 | 必须取得的证据 |
|---|---|---|
| G0 · 基线与可行性 | 固定当前提交和工作区差异；保存既有用户改动；建立新旧对照；验证固定 Pi SDK 长挂起/取消/重启、禁用独立 IO，以及原生认证阶段证据。 | 契约测试与支持矩阵；真实环境不足明确阻塞。不得以输出正则代替可信业务启动边界。 |
| G1 · 最小安全闭环 | 完成身份、正交结果、审批等待、审计 ACK 与单一派发守卫，接首切片 fixture。 | 普通失败继续；缺 ACK/许可失效不派发；三模式与硬门对照；认证拒绝不误判为业务失败。 |
| G2 · 完整业务与故障恢复 | 同一首切片接只读核验、风险域锁、一次确认继续、显式上下文和作业观察。 | 正向/失联两分支，用户拒绝/取消/停止、迟到退出、重启恢复全部通过；不重放未知动作。 |
| G3 · 获准隔离真机验收 | 在显式获准的隔离主机与模型环境跑同一任务。 | 真 SSH/PAM、文件发布、配置、服务和健康证据；区分 fixture、协议模拟和真机结论；形成新旧体验报告。 |
| G4 · 受控切换 | 按会话绑定新实现；验收数据迁移与历史、未决账兼容；删除已接管旧入口。 | 单一写路径，切换/崩溃/恢复测试，依赖门禁通过；不拿真实业务双写做对照，不盲目回滚旧版本。 |
| G5 · 工具面与人工底座收敛 | 分批迁移五域动作；独立验收后将人工终端接共同底座，保留现有交互。 | 旧能力逐项对照、人工隔离、混合时间线及盲区可见；不为“只剩五工具”牺牲清晰 Schema。 |
| G6 · 知识与扩展 | Skills → 受限知识 MCP → 多主机 → 一层子代理。 | 各模块独立授权/披露/恢复验收，见工程篇；Go、对外 MCP 不自动进入此阶段。 |

G0–G2 默认使用合成凭据、假模型、本地协议 fixture 或明确获准的一次性环境；不得访问个人数据或生产主机。G3 须另有隔离真机和付费调用授权。本文件本身不授予这些权限。

## 6. 验收指标与记录方法

### 6.1 安全与业务门优先

- 无凭据泄露、越权派发、未知变更自动重放、人工输入权借用。
- 每次授权和许可受确切内容、身份、目标、策略、代次、时效约束；三个模式都不能免除。
- 服务 active、exit 0、文件哈希一致各自只证明对应观察，不等同业务整体成功。
- 核验不足时明确范围，不能为通过请求数指标少做检查或提前宣告任务不可能。

### 6.2 体验对照

| 固定基准场景 | 目标 |
|---|---|
| 已有充分事实证明能力不足 | 主会话请求 ≤2、可避免整轮暂停 0；说明缺失条件和可选路径，而非把未知当不可能。 |
| 可完成的常规部署 | 主会话请求 ≤7、可避免整轮暂停 ≤1，优化方向为 0；完整业务验证不减少。 |

旧稿“10 请求 / 3 暂停”仅作历史描述，不能代替 G0 重测。固定模型版本、思考档位、提示词/策略、初始主机快照、用户输入和任务终点；预先固定样本与重复次数，报告每次结果及分布，不挑一次最好成绩。

统一计数：

- **请求**：每次实际发给模型供应商的生成请求计一次；主会话、独立审核、摘要/压缩、重试分别列出并报告总和。上述主会话目标不能隐藏额外模型成本，额外请求与费用也须对照解释。
- **工具调用**不等于模型请求；一次生成可提多次调用，依赖操作仍须等待结果。
- **等待/交互**：执行裁决、身份选择、私密认证、任务澄清、未决风险承担各计一次独立事件。
- **整轮暂停**：必须另发消息或点击继续才恢复任务；必要用户等待不因改名称而消失，报告等待时长和操作数。可避免暂停单列具体原因。
- **成功与成本**：业务成功率、首次有效工具延迟、总时长、输出 token、重试、有效替代方案、人工操作数、未决重放数同时报告。

“询问单调递减”改为同样本统计非增目标：模式一 ≥ 模式二 ≥ 模式三。允许等于；模式三在预授权内执行类询问为 0，但认证、澄清及风险承担仍可发生。不用强制少问诱导模式二假装确定。

## 7. 复用、迁移和维护纪律

- 现版留作对照/兼容基线，不整块复制旧 Agent；可靠模块经契约复验可复用。不要重写 SSH、凭据和数据库只为满足“从零”。
- 继续遵守 `AGENTS.md`、版本固定、版本化迁移、800 行及依赖检查；自动测试只在 `Tests/`。
- 一项业务职责同时只有一个活权威；临时桥只翻译协议，不能保留双审批表、双计时器或两条写入路线。
- 回滚软件前检查审计 schema、Pi 会话和未决锁兼容；已派发操作不随版本回退重跑；不兼容只读历史或走经验证迁移。
- 行为/分级/授权范围变化要更新策略版本、失效等待与许可、补正反例；不得用提示词绕过安全实现。
- 维护性验收至少增加一个失败分型和一个主机适配实例；改动应落在对应归约/适配职责，UI 不新增派发判断。

## 8. 每阶段报告与剩余设计点

报告须包含：提交与工作区范围、实现/未实现项、测试命令和结果、跳过与环境限制、真机证据、体验统计、策略/数据兼容影响、下一阶段阻塞。不把本地测试通过写成生产已验收。

G0/G1 前须交付具体方案：

1. 原生 SSH/sudo/su/PAM 支持范围及可信阶段证据；无法证明时如何安全收尾。
2. 模式二的用户委派范围、可核对的自审条件、独立审核选项和失败升级语义；不得只留下“拿得准”。
3. 长作业观察窗口、输出上限、轮询/模型请求节奏、超时和无进展预算。
4. 结构化文件身份、版本条件、元数据、原子发布与恢复的支持边界。
5. 审批时限、事件/输出留存与隐私、旧会话和未决账迁移方案。

这些是实现前的具体设计产物，不撤销本页已确定的边界；若做不到则回报，不以临时豁免替代。

### 8.1 原需求模块去向

| 原模块 | 本轮处理 |
