# CloudHelm v5.3 · 工程边界与状态契约

> **状态：评审后重写的目标规格，尚未实施。** 替代同路径旧提案；范围、顺序和验收以[实施计划](V5_3_REFACTOR_PLAN.md)为准。具体主机行为见[主机访问规格](V5_3_HOST_ACCESS_DESIGN.md)。字段与职责名是契约示意，不要求逐项建立类，不新增顶层包。

## 1. 包依赖与进程责任

```text
application → core
adapters → core
desktop 装配入口 → application + adapters + contracts
renderer / preload → contracts
```

| 边界 | 拥有的职责 | 禁止 |
|---|---|---|
| Core | 业务事实、端口、风险分类、结果归约纯规则、授权绑定规则 | 导入 Electron/Pi/SSH/SQLite 或持有运行时调度 |
| Application | 任务、交互等待、操作编排、许可、准入、核验、写锁和恢复 | 读取 UI 状态作裁决、导入具体适配器 |
| Adapters | Pi、SSH/认证 PTY、文件 IO、解析器、SQLite；产生真实观察 | 自行决定业务重试、换身份、审批或风险解锁；适配器相互导入具体实现 |
| Contracts | 窄 IPC/RPC、输入校验及展示 DTO | 作为领域语义权威、从 UI 标签反推状态 |
| Desktop Main | 窗口、OS 凭据、IPC 接收方校验、持久提交服务和投影 | 第二套任务/审批状态机、前端决定解锁 |
| Desktop Worker | 运行 Application、装配适配器、进程/RPC 与薄桥 | 在装配代码继续积累业务分支与业务计时器 |
| Renderer / Preload | 显示后端投影、收集具名用户动作、UI 临时状态 | 决定投递目标、身份、权限、派发或恢复 |

依赖单向不表示禁止事件或端口回调。适配器可通过 Core 端口报告观察，不能回调上层业务决策；Application 决定后续。物理连接由适配器持有，逻辑上下文由 Application 持有，不建包揽一切的“主机万能管理器”。

## 2. 互不替代的控制门

| 门 | 判断什么 | 是否随三模式改变 |
|---|---|---|
| 硬门与目标授权 | 任务/主机范围、硬禁令、用户保护路径、受支持操作形态 | 否 |
| 信息披露 | 哪些数据可读、可送模型或外部服务，来源/去向/秘密边界 | 否；用户批准执行不能允许凭据泄露 |
| 操作裁决 | 这项风险在当前授权内由规则、用户、自审或预授权处理 | 是 |
| 身份与凭据 | 身份选择、可信认证窗口、唯一接收方、挑战生命周期 | 否 |
| 写入准入 | 队列、主机风险域、未决结果、仍运行的作业 | 否 |
| 派发守卫 | 内容/身份/目标/时效/代次是否仍匹配，提交 ACK 是否有效 | 否 |

所有 AI 和系统发起的外部操作进入受控入口。系统探测只允许固定、有界、只读模板，不靠 `actor=system` 或模型自称探测获得豁免。人工终端入口独立，不套 AI 操作裁决，但不豁免主机信任、会话归属及隐私要求。

**风险未知 ≠ 系统不可执行。** 可承载但无法确定影响的提案按模式裁决；解析基础设施故障、认证无法隔离、缺少 ACK、许可过期、范围越界等导致当前操作不派发。拒绝当前操作不自动停止整项任务。

## 3. 三模式的准确语义

先查硬门、披露、支持能力和已知准入，再进行操作风险裁决；真正派发前重复最终复核。

| 风险 / 控制 | 模式一：询问优先 | 模式二：显式自审 | 模式三：预授权执行 |
|---|---|---|---|
| 已识别只读、常规变更，符合授权 | 规则允许 | 规则允许 | 规则允许 |
| 高影响/不可逆、可承载但影响未知 | 挂起本工具等待用户 | 返回 `adjudication-required`；重提确切操作和依据，满足委派条件后允许，否则升级 | 命中用户预授权范围自动允许；越界返回未执行，不改成隐式授权 |
| 硬禁令、保护路径、凭据泄露 | 拒绝/安全投影 | 相同 | 相同 |
| 身份选择、私密认证、未决风险承担 | 各自独立用户流程 | 相同 | 相同 |
| 安全/存储故障或能力不支持 | 当前不派发 | 相同 | 相同 |

### 3.1 风险分类纪律

四类为：已识别只读、常规变更、高影响或不可逆、影响未知。分类依据是完整内容、参数、目标、cwd、执行身份和环境，不是程序名。

- `cat/ls` 不自动免除敏感信息披露检查；`systemctl status` 不等于任何 systemctl 调用只读。
- 重启普通业务服务也可能中断业务；停止 SSH、修改防火墙、写 systemd 单元、启用开机服务等不得因“部署必要”自动归常规。
- 提权不是风险等级。root 查询可只读；普通用户删除数据也可高影响。
- 任意脚本/解释器/安装钩子不能凭文本证明只读，不当作普通查询。
- 保留现版硬禁令、用户保护路径及凭据底线。扩大模式权力、重分类、豁免须显式策略版本、所有者确认及正反例；本次方向批准不等于每一条生产分级已经变更。

唯一生产规则在 Core；Application 路由执行，工具、UI、提示词和适配器不得维护分级副本。

### 3.2 模式二不是独立安全审查

第二次调用提供关联 ID、确切操作和依据/证据引用。后端核对未过期、未被拒、内容/身份/目标相同、证据属于本授权范围、自动裁决落在用户委派范围内；只核对这些不代表代码理解了理由是否正确。

**同模型重提仅保证显式第二次确认，不保证模型“拿得准”。** 没有可验证的委派条件或模型声明不确定时升级用户。主观确信不能扩大委派范围。可选独立审核走明确配置的端口，不静默换模型、计费源；其意见也不能跨越硬门。G0/G1 须冻结可测试的自审条件和自动/升级样本，禁止把“AI 自己负责”作为未完成设计。

记录真实依据来源、证据引用和结果；不得要求模型披露内部思维链。模式三记录 `decisionSource=user-preauthorization` 和命中范围；可以标记 `autoAdjudicated`，但不生成模型事前未做过的分析或理由。

## 4. 状态权威与连续性

不得用一个 `status` 同时代表模型、授权、连接和远端进程。

| 事实 | 唯一运行权威 | 持久/展示边界 |
|---|---|---|
| 任务目标、预算、控制代次、用户停止 | Application 任务协调 | Main 提交业务记录，Renderer 投影 |
| 审批 pending、计时、取消、重复答复 | Application 交互协调 | Main 搬运并提交；不保留第二份等待表 |
| 风险决定及派发许可 | Application 裁决/守卫 | 决定可审计；许可为进程内单次能力，不能恢复 |
| 连接、认证阶段、活性及退出观察 | Adapters | Application 校验来源并归约；审计保留限制 |
| 风险域未决账与写入准入 | Application 风险协调 | 已提交未决事实可恢复；UI 不乐观解锁 |
| 核验和恢复 | Application 恢复用例 | 明确 evidence/风险承担；不改写原尝试 |
| 已提交历史 | Main 经存储端口提供的提交事实 | 数据库不是活进程真相；迟到结果追加而非覆盖 |

任务至少区分可推进、等待具体交互、需要核验、用户停止、已回答等语义；模型活动、远端作业和写入阻断分别投影。`needs-verification` 可以允许只读工具，不是自动 `abort`。真正模型结束不表示业务目标已验证。

普通失败按[实施计划的连续性表](V5_3_REFACTOR_PLAN.md#3-连续性必须实现的行为)继续。后端返回有限下一步能力，如读取日志、只读核验、修正未派发提案、请求用户身份选择；这些是当前约束，不是批准下一项操作。每次调用重新检查。

## 5. 正交结果协议

### 5.1 执行事实

字段名可调整，信息不能混淆或省掉未知：

```text
operationRef / attemptRef / actor / task / host
handoff: not-sent | handed-off | unknown
businessStart: not-started | started | unknown
liveness: running | exited | unknown
exit: observed code or signal, otherwise null
 effects: none | possible | observed-change | unknown
identity: requested / observed / evidenceSource
output: tail / truncated / captureComplete / logRef / observedAt
context: operationCwd / defaultCwd / revision / rebuilt / restoreStatus
blockers: typed reasons and related operation refs
nextActions: bounded currently available actions
```

上面是字段词汇，不要求 `not-sent` 同时有退出；未发时活性可未知。`effects:none` 需可信未启动或可靠的无副作用证据；非零退出码、缺少日志、认证文本、进程不存在均不足以单独证明。业务未启动也不自动证明认证/登录初始化对整台机器零影响，需注明观察范围。

### 5.2 工具回执

| 回执 | 含义 |
|---|---|
| `done` | 本次调用已返回最终已知事实，可含非零或结果未知；不等于业务成功 |
| `running` | 有观测时点和可查询作业引用，不代表永久活性或应用就绪 |
| `adjudication-required` | 未获本提案派发权，等待绑定的自审或升级 |
| `rejected` | 当前候选未获执行；含用户、硬门、能力或失效原因；不自动终止任务 |

一次调用可能包含 sudo 尝试和另一个 su 候选，必须逐尝试保留事实；后续候选 rejected 不能抹掉先前已派发的尝试。运行转未知与取消请求都可有新观察事件，不把工具超时当远端退出。

输出先脱敏再裁剪；返回头尾或错误摘要与分页引用，必须标明完整性。长日志通过 Journal 的授权分页读取，不能为重新拿输出而重跑命令。事实优先，必要行动提示简短明确；不返回大段政策说教，也不删除理解结果所必需的限制。

## 6. 裁决、提交与单一派发

1. 登记提案、规范作用域和尝试引用；读取当前策略、身份及上下文快照。
2. 检查硬门/披露/能力及已知阻断，分析风险，按模式获取决定。
3. 用户交互由 Application 挂起，不持有执行槽、主机队列锁、SSH 通道或活进程锁。等待期间不轮询模型；软提醒不等于硬过期。
4. 持久提交确切提案、决定和派发意图；收到匹配 ACK 后才能进入派发。
5. 进入队列后在传输交界复核所有绑定并单次消费许可；失败则未派发并记录原因，不回用旧许可。
6. 收集独立观察、归约并提交结果；迟到观察按原尝试关联，不覆盖新控制代次。

最终复核至少包括：内容/文件版本、主机配置及风险域、cwd/环境修订、登录/执行身份、策略/模式及委派范围修订、连接/终端/控制代次、接收方、时效、用户停止、准入和 ACK。

`adjudicationId` 只是关联引用，不是 bearer token。许可不交给模型、Renderer、Journal 或恢复文件。换身份、内容、目标或连接须重新裁决；已批准不等于有执行槽。

没有 ACK 不派发；边界不明时不外推“没有收到回执所以没执行”。本地单次许可不承诺远端 exactly-once，持久 ACK 也不冒充断电级耐久保证。进程崩溃后旧等待和许可失效；不能从历史批准恢复自动执行。

## 7. 核验、未决锁与恢复

- 对可能变更的未知/部分生效项保留跨任务风险域写锁；只读失败本身不制造业务写锁。
- 已知运行作业与未知结果分开显示；仍可信运行的变更作业不能借风险承担清锁。
- 只读核验有独立调度入口及授权，不能被正在等待的审批或未知写入占槽死锁。
- 对账证据关联原操作、主机/身份、目标、时点和内容版本；新连接、历史人工日志或模型一句“已处理”不能解锁。
- 证据足够先持久提交，再同步解除对应项；不足只可明确风险承担。用户接受风险不把原记录改成成功、不代表验收通过。
- “拒绝”“仅解除”“接受并继续”是不同具名动作。继续需 ACK、实际解锁、其他阻断清除、任务仍授权、控制代次未变、用户未停止且预算可用。
- 回执丢失不得自行反向回滚已提交决定或猜测已解锁。重启从权威账对账；动作 ID 幂等，迟到回复不重放业务。

事后核验分三层：派发内容与批准一致；结构化目标前后内容/元数据/收据；指定服务/协议健康证据。任意 Shell/第三方工具的全机副作用通常不可见，必须标 `unobserved`，不把“没发现越界”写成“证明无越界”。

## 8. 工具域契约

域按心智动作组织，首切片只注册必要动作；扩展未装配时不对模型宣称可调用。五域不是新增万能执行器的理由。

| 域 | 目标动作/边界 |
|---|---|
| shell | exec、snapshot、kill、reset、context；隐藏载体选择，不暴露裸 SSH 或普通字节输入 |
| file | read/write/upload/download；结构化修改还需预览/版本条件/恢复语义，可收在 action 内；Skills 库只读，本地仅用户选定范围 |
| ask_user | clarify、escalate；执行裁决必须关联后端待决项，不能把普通文本答复当许可；凭据不走此聊天工具 |
| journal | 授权内任务/操作/错误/裁决/能力/知识/人工事件及日志分页，来源、时点与盲区可见 |
| mcp | 目录按需查询和 call；同一工具域，不把所有工具定义常驻上下文 |

各 action 使用清晰的判别联合 Schema，拒绝无关字段；不建立大量可选字段的万能参数表。业务身份统一 `current / root-required`；工具无密码、runAs 任意用户名、连接句柄或执行通道参数。

模型主动操作指定文件优先 file；grep、编译、解压、安装产生的 IO 不按字面禁止，仍按真实影响裁决。不提供业务部署黑箱包；内部固定只读核验模板可复用并逐步留痕，无须变成额外模型工具。组合命令只要受支持且完整审核可使用，不再为了少数限制一律拆碎，也不把请求数目标变成大脚本批执行。

工具清晰性高于机械词汇禁令：必要时可以解释某能力不可用，但不让模型选择 SFTP/PTY/Go 路线。plan/delegate 为后续接点，不装配、不占首切片实现。新增域须论证，七域上限是产品约束而非安全机制。

## 9. Pi、Skills、MCP 与子代理边界

### 9.1 Pi

保留固定版本的 AgentSession、SessionManager、压缩、流式事件与队列能力；CloudHelm 业务记录与原生模型 transcript 各有权威，不用 UI 展示文本重建完整模型历史。不启用未经自有授权的内置读写/Shell、环境凭据回退、项目资源发现或外部执行扩展。

G0 验证长等待、取消、超时、重复回答、重启与工具结果对应，验证明确工具清单和 Skills/MCP IO 可关闭；长等待失败应回报，不自动重发旧工具。上下文压缩保留任务目标、已知事实/证据引用、用户拒绝/停止、未决项与待解决问题，不能仅总结聊天语气。预算包含所有实际模型请求。

### 9.2 Skills（G6）

纯知识，不定义工具、不授予权限。元数据常驻有界，正文经 file 授权只读加载并记录版本/摘要；远端输出或 Skill 中的指令均不改变授权。

AI 草案通过后端具名的提案动作提交（可挂 ask_user 域），不能直接 file.write 技能库；用户审阅决定绑定精确草稿摘要、版本、目标和时效，随后后端生效并保留旧版本可回滚。用户手写内容也经过格式、路径和可见范围检查，不能加载代码扩展。撤销/重复/并发更新/迟到批准均测试。

### 9.3 MCP（先限定外部知识查询）

自有客户端位于安全入口后，协议库可复用，不能沿 Pi 独立通道执行。用户配置 server、传输、凭据与允许工具；信任标签只是授权输入，不证明 server 只读。

逐调用同时检查 server/tool/args、数据披露去向、上下文范围、当前模式、超时/大小/并发与调用关联。未知第三方返回按不可信资料处理；内容不能触发自动工具、执行资源链接、扩大权限或泄露秘密。动态工具目录变更使绑定失效，重新审核。

首版远程知识 MCP 不启动任意本地 stdio 程序；后续本地进程需独立用户配置、进程/文件/网络隔离方案。server 的 sampling、elicitation、roots、资源读取等额外协议能力默认关闭，若支持则逐项通过自有入口，不能称“兼容所有 server”而默认放开。server 认证不进入模型或审计正文。

JSON Schema 同构仅降低适配成本，不等于对外 MCP 零成本。对外 MCP 若立项，由本系统送达审批，不以外部 elicitation 支持度作为安全唯一前提。

### 9.4 多主机与子代理

首版拒绝任务扩授第二台主机；后续每个子代理有独立上下文和更窄授权、预算、父子审计，一层为限，不递归。父任务停止撤销后续派发；子代理结果不会自动授权主任务。同主机写锁跨所有任务/代理共享；不让并行成为旁路。

## 10. 审计、隐私与离线回放

关联链：发起方（AI/用户/系统）→ 任务/主机 → 请求或用户动作 → 工具调用 → 操作/尝试 → 决定/许可消费事件 → 观察/证据 → 风险承担/恢复。ID 由后端生成并约束，不相信模型提供的身份标签。

- 模型会话保存实际可安全留存的输入/输出、模型及工具 Schema/提示词/策略版本、压缩分支与内容摘要，足以解释当时模型见到的授权上下文；不是保存 HTTP 认证头、私密输入、加密思考载荷或供应商隐藏内部状态。
- 业务审计、模型 transcript、诊断元数据分开；业务/模型记录的隐私、存储权限、限额和清理须明确。诊断日志不增加聊天、命令和输出正文。
- 凭据不入模型、命令参数、普通日志或审计。敏感读拒绝或只提供安全投影，任何模式的“批准”不能放出原始秘密。
- 人工终端只记录可信事件与可识别边界，失效有盲区标记；不记录全量按键补缺。AI 查询仅同授权范围、相关且脱敏有界，不能任意浏览人工原始流。
- 回放是只读时间线重建，说明来源和完整性；不重新连接、调用模型或执行命令，不宣称确定性重演。事件因果顺序可确认，跨来源时钟不能伪称精确全序。
- 脱敏无法保证识别任意秘密；已知敏感源先阻断，流式脱敏补充防护。无法安全公开的正文不回流；截断、清理及缺失记录明确展示。

## 11. 契约测试、迁移与退出条件

测试集中 `Tests/`；先固定现版应保行为，再给新目标写失败用例，不把旧错误写为正确行为。

| 矩阵 | 最少验证 |
|---|---|
| 连续性 | 参数修正、缺工具替代、无副作用失败不中断、拒绝不绕过、取消不重复索密、用户停止不自动醒来 |
| 三模式 | 正常路由、自审绑定/升级、范围外不执行；全部注入缺 ACK、超时、代次/模式变化和重复许可均不发送 |
| 结果 | 未交接/已交接未知、启动未知、非零无影响、部分影响、停止请求不是退出、输出截断 |
| 恢复 | 核验独立入口、同主机跨任务锁、迟到结果、提交失败/回执丢失、仅解除与接受并继续区别 |
| 隔离 | 工具无裸执行句柄、Pi 无旁路、人机误投拒绝、Journal 越权/秘密防护 |
| 迁移 | schema 回滚/失败、旧历史只读、未决锁恢复、会话路由切换、Worker 丢失及应用重启 |

迁移从 Worker 的任务/审批/派发/恢复业务逐切片移到 Application；Main 留持久化边界，SSH/Pi 留适配器。临时桥只翻译，不能保留双权威、自动旧路径兜底或真实双写。当前人工终端先保留，独立验收后再切底座。

交付终态以业务权威和依赖检查确认：范围内 Worker 仅装配/RPC，没有第二套业务状态机/计时器；旧入口已删除；普通错误处理可在归约/用例单点演进；所有新增外部能力沿相同门扩展。文件移动、类数量减少或单元测试通过均不能替代业务验收。
