> **状态：评审后重写的目标行为规格，尚未实施。** 替代同路径旧设计。范围与验收以[实施计划](V5_3_REFACTOR_PLAN.md)为准；状态、许可及三模式以[工程契约](V5_3_ENGINEERING_BOUNDARIES_PROPOSAL.md)为准。本篇不授予真实服务器、付费模型或个人凭据访问权。

## 1. 底座形态与首版范围

一个主机访问底座，两种互不授予权限的入口：

```text
模型 → 自有工具 → Application 受控操作/安全门 → SSH exec / 受控认证 / 文件 IO
用户 → 窄人工终端用例（主机信任、归属与隐私） → 独立交互 SSH
                                    ↓
                  共同配置与连接基础设施、受权限裁剪的审计
```

首版单主机原生 SSH，不依赖远端 Python，不新增远端常驻 Agent、不自动安装依赖或 Go 组件。业务命令无通用交互 stdin；专用认证 PTY 是绑定操作和接收方的例外，不给模型普通键盘输入能力。人工终端天然有交互，但永远不成为模型工具。

物理连接、通道与认证句柄在 Adapters；任务逻辑上下文、身份路径选择、作业租约与恢复在 Application；凭据在客户端受控边界。工具不能拿裸连接或输入句柄。

支持平台须实测声明。首切片以获准的 Linux/SSH/sudo/su/PAM 环境为范围；“原生 SSH”不等于兼容任意 Windows、BSD、受限 Shell 或认证配置。能力不足返回事实，不猜测执行，不自动安装补齐。

## 2. 逻辑上下文，不是持久 Shell

作用域至少 `(taskId, hostId)`，再绑定主机配置修订、登录/执行身份、连接/终端/控制代次。主机配置改变不能把旧任务静默指向新连接目标。

| 状态 | 目标行为 |
|---|---|
| 初始目录 | 从当前授权连接观察登录目录；未观察成功不臆造。 |
| 默认 cwd | 通过 `shell.context` 的显式动作修改；验证确切身份可进入、提交成功后更新上下文修订。 |
| 单次 cwd | `shell.exec.cwd` 仅覆盖当次；命令里的 `cd` 只影响当次进程，不修改跨轮默认值。 |
| 环境 | 只允许应用已授权、非秘密的配置引用；不接受任意模型环境转储或继承远端隐式状态。 |
| 重建 | 同一授权目标上加载最后确认的 cwd/环境修订，按执行身份复核；恢复结果明确。 |
| reset | 清除逻辑上下文、递增修订并撤销相关待派发许可；不杀作业、不删历史、不清未决写锁。 |

示例：默认 `/home/deploy`；`exec(cwd=/opt/myapp, command=ls)` 后默认仍为 `/home/deploy`。显式设置默认 `/opt/myapp` 成功后，后续 exec 才默认使用它。`cd /tmp && ls` 不改变跨轮默认目录。

不保存/恢复任意 `source`、函数、别名、trap、Shell 选项、文件描述符或人工终端状态。虚拟环境优先明确解释器路径或已批准的环境配置；不能以“已激活”记忆推断下一次执行环境。

环境配置可能改变命令含义：PATH、动态载入、解释器启动等需白名单及版本绑定；不从 `.env` 或 `env` 读取秘密注入模型，不把普通用户配置自动用于 root。首切片无必要则不开放环境修改动作。

每次结果区分 `operationCwd`（实际验证、未确认则空）、`defaultCwd`、上下文修订、`rebuilt` 和恢复明细。目录缺失/无权限不能静默回家目录或 `/` 继续写入；模型可查询并请求新的明确上下文。root 目录在受控目标身份内复核，不能由普通账户检查失败推出 root 无权限。

## 3. 操作级身份与受控认证

### 3.1 模型与用户分别声明什么

模型只提交业务动作、目标、cwd 以及 `identity=current | root-required`，不提交密码、任意 runAs、连接参数或认证策略。示意：

```json
{
  "action": "exec",
  "hostId": "authorized-host",
  "command": "systemctl start demo.service",
  "identity": "root-required",
  "cwd": "/"
}
```

业务动作不嵌套 sudo/su；首切片对此返回未派发并允许改为身份声明，不因此暂停任务。已有可信 UID 0 观察时直接使用当前 root，仍按该身份裁决。名字叫 root、旧连接 UID、能力卡均不是当前身份许可。

默认使用受控 sudo；用户可明确选择当前任务的受控 su 路径。路径选择绑定任务、主机配置、登录、目标身份、控制/连接代次和时效，可撤销；不是业务批准，不跨任务继承。代次变化后重新确认，不静默恢复到旧高权限路径。

### 3.2 sudo → su 的严格条件

只在以下条件同时成立时提出同一业务动作的 su 候选：

- 当前 sudo 尝试有可信来源证实业务未启动；原记录完整保留。
- 原因确认为工具不可用或本次授权受限，而非密码错误、用户取消、未知或业务失败。
- 没有相关未决写入阻止新尝试；新身份仍在用户可选择范围。
- 用户明确选择 su，然后为新尝试建立新的精确操作绑定和裁决。

用户选择有效路径后，后续符合条件的动作可复用路径选择，不复用审批、密码或挑战。首切片 su 逐操作认证，不缓存 su 密码、不建立常驻 root 会话。不强制安装 sudo、不修改 sudoers、不自动改用 root SSH。

### 3.3 私密挑战生命周期

1. 有效操作经过裁决与准入，执行器仅在可信认证阶段请求专用挑战。
2. 挑战绑定操作/尝试、主机、身份、连接/终端/控制代次、接收方、有效窗口和时限。
3. 客户端专用窗口收取答复，经受控 PTY 注入到唯一认证接收方；不能放在命令参数、环境、普通业务 stdin、远端文件或日志中。
4. 答复一次性消费；重复、迟到、取消、断线、接收方变化或业务阶段已开始均拒绝。
5. 无法抑制回显或区分认证阶段时，不开放注入。超时/失败清理本次秘密及挑战，不自动再次索取或换身份。

SSH 登录密码、私钥口令、OTP 和 sudo/su 挑战用途分离，不按 SSH 登录方式猜提权密码。未观察到可信提示就不索取；注入成功、提示消失或 PTY 关闭均不是认证成功证据。现有 sudo 内存复用机制如保留，须独立复验精确绑定、失效与清理，不扩大到 su；具体生命周期在 G0/G1 方案中冻结。

### 3.4 五个必测分支

| 场景 | 应返回与后续行为 |
|---|---|
| 密码提示前拒绝 | 允许无提示分支；可信未启动才允许提出替代身份。仅看到 sudoers 文本或非零码则只作诊断，启动状态未知不回退。 |
| 认证后授权拒绝 | 分开“认证通过”“本次授权拒绝”和“密码失败”；仅能证明未启动才无业务写锁并可提出 su。 |
| 当前已是 root | 使用绑定当前代次的 UID 0 证据，无多余提权挑战；操作裁决和锁不豁免。 |
| 用户取消 | 区分派发前、认证中、交接后取消；未启动可不新增业务锁，边界不明仍保留未知；不自动索密或换身份。 |
| 业务打印相似拒绝文本 | 按业务结果处理，不能误判认证拒绝；不推断无副作用，不自动换身份重跑。 |

**可信阶段证据是 G0 可行性门，不是文档已经解决的技术事实。** 认证提示标记只能绑定输入窗口；缺少启动标记不证明未启动，出现交接前标记也不证明业务已经运行。任意业务输出可伪造文本，普通 nonce/退出码/正则本身不等于隔离证据。原生通道若无法可靠区分，保留 unknown 并回报支持边界，不临时放置 helper、恢复 Python 或偷偷引入 Go。

提权协调的现有定位入口：`worker/operation-privilege.ts`、`core/privilege-routing.ts`、`core/sudo-outcome.ts`、`adapters/native-ssh-pty.ts`、`adapters/ssh-command-terminal.ts`。保留思路和已验证组件，但现有诊断推断不能直接提升为目标契约的证明。

## 4. 文件操作：身份、版本与提交完整性

file 是主动文件 IO 的首选，远端及用户选定本地范围都经统一授权。结构化参数改善分析，不自动使任意写入安全。

- read 返回有界 UTF-8、路径/身份、来源、完整性、版本摘要；截断或脱敏内容不授予完整替换依据。敏感源拒绝或只出安全投影，模式批准不能放出秘密。
- write 区分仅创建和基于版本的更新；目标存在与版本变化不能用普通覆盖掩盖。预览不等于提交许可。
- root-required 同样适用于文件动作；普通账户对 `/etc` 不具写权限，不能依赖普通 SFTP 自动获得提权。
- 支持的特权发布可采用已授权范围中的非秘密暂存、单独审核的目标身份提交、读回复核；每一步有可见操作记录和确切内容绑定，不是模型临场绕过 file 的脚本方案。
- 发布前核对目标/源版本、路径与符号链接、所有者/权限及受支持元数据；明确原子替换、备份和恢复收据的保证范围。身份变化、同目录临时文件、硬链接/rename 不能替代完整安全论证。
- ACL/xattr、符号链接竞态、断线中途、无 SFTP 等无法满足的情况返回具体 unsupported/conflict/unknown；不假装完整事务，不自动退到 heredoc 或删除重建。新建非秘密文件可作为首切片最小范围，覆盖已有文件另过门。
- 恢复需新裁决并检查当前目标未被其他操作修改；清理备份也需明确目标及规则。不保证失败自动回滚，不在未知状态下盲目补偿。
- 上传/下载限制来源、目的地、大小与秘密；下载到客户端是信息披露，上传只使用用户选定材料。不沿符号链接逃出选择范围。

文件内容摘要、必要元数据与步骤引用进入指纹和审计，秘密正文不进入。目标内容读回证明内容观察，不证明没有其他副作用。

## 5. 能力卡：减少撞墙而不制造虚假确定性

首次授权接触主机时，固定有界只读探测蒸馏卡片；来自系统的探测也走统一入口并留 `actor=system` 审计。卡片不是执行许可。

| 类别 | 首版观察来源 | 局限 |
|---|---|---|
| 平台 | `uname -s/-m/-r`；按数据读取 os-release 的 ID/VERSION_ID | 内核架构不是用户态 ABI，发行版声明不保证工具存在，不 source 配置 |
| 身份/目录 | `id -u/-un`、受支持的 `pwd -P` | 只证明该身份与时点；不能证明下一条 sudo 的授权 |
| 工具/服务线索 | 固定 PATH 的有限 `command -v`：sh、env、sudo、su、systemctl、systemd-analyze、包管理器、必要传输/诊断程序；Linux 可有界观察 PID 1 | `present/absent/unknown`，存在不等于可用；systemctl 存在不等于 systemd 可管理 |
| 可选接触快照 | 针对已确认目标目录的 `df -Pk`；Linux 有界解析内存字段 | 带时点，缺失不阻塞；容器宿主内存不能假装任务配额 |
| 客户端事实 | 主机授信、认证通道、已验证的输出观察/停止能力 | 只报能力，不报密码、挑战原文或私钥；停止能力不保证已退出 |

探测不读 sudoers、不跑猜测权限的 sudo 样板、不枚举所有环境、不扫描全机、不触发认证。基本探测建议以现有 5 秒/16 KiB 有界逻辑为起点，G0 验证并固定总调用/时间上限；部分失败记录未知，不拖住业务。默认 Shell 及虚拟化不是首版必填。

每项事实有来源、观察时间、适用身份/连接代次、修订和有效范围。卡片数行摘要、有明确大小上限，原始证据按需分页；首用懒注入，变化随下一次已授权请求/结果附 delta。丢失增量可查最新卡片修订，不只依赖对话记忆。Journal 可恢复历史与新鲜度；离线查看不自动连接，旧卡不当当前授权。

重连、身份/配置变化使相关缓存失效；迟到探测不覆盖更新代次。易变资源水位按需刷新，不因卡片有 TTL 就自动不断请求模型。

**权限事实必须保守：** sudo 存在、用户组、某条历史 NOPASSWD 均不证明任意命令可执行；没有保存 root 密码也不证明无法部署。只有充分证据才判断“不可能”，否则明确尚待确认的路径。具备用户态安装、不同端口或受控身份等合法替代时，应允许模型评估，而非直接收尾。

## 6. 长命令、作业观察与停止

exec 先等待一个有界观察窗口：已知退出返回事实；未结束且有可信作业绑定时返回 running 与引用；无法判断活性时返回 unknown，不能为用户体验伪造 running。

- 作业绑定任务/主机、操作/尝试、身份、连接/载体代次和已观察进程身份。模型只拿查询引用，不拿进程控制能力。
- snapshot 返回观测时点、活性、累计/增量输出、完整性和退出信息；没有输出不是卡死，SSH channel 关闭不是进程退出。
- 大输出分页、先脱敏再裁剪；不要靠重复执行获取全文。轮询有最小间隔、并发与预算限制；未变化快照不应引发无限模型轮次。
- kill 是受控停止请求，须复核精确目标；返回信号发送/拒绝/未知，只有实际退出观察才能确认结束。
- PID/PGID 与 starttime 检查可降低误杀风险，但检查到发送之间仍可能竞态；不承诺原生路径无竞态“精确终止”。证据不足不发，能力如实标注。
- 不让一般后台作业默认阻止核验；相关潜在写入作业在未结束前保留风险域写入准入限制，不能为并发而解除。
- 用户停止任务、暂停模型、停止某作业、断开连接分开。用户主动停止后后台事实只记账，不自动唤醒模型。
- 应用重启丢失控制能力时重新观察，不承诺重新附着旧前台进程或控制逃逸进程；缺可靠证据保持未知。

现有 native-background 的 setsid、日志尾标记与 `/proc` 观察需要保留真实限制：业务可污染日志、zombie、退出标记缺失、PID 复用和进程逃逸均不能靠输出格式抹去。G0/G2 明确支持范围和可信度，必要时限用现有服务管理器查询，不把该路线直接当作通用持久作业系统。

观察窗口、输出字节上限、后台总数、最大等待、无进展/费用预算在 G0/G1 固定配置和测试；正常无输出的长任务不因“没有新文本”自动判失败。独立只读查询可有界并行，依赖前一步结果的操作按因果顺序推进。

## 7. 断线、写锁与恢复

### 7.1 断线当时

撤销该代次许可、认证挑战和失效等待，按已有证据分别记录：未交接、已观察完成、已交接或边界不明。潜在变更的未知项进入主机风险域未决账；单纯只读失联不增加业务写锁。

用户主动断开/停止、指纹变化或目标授权变化不能触发自动绕过。存储失败保持保守阻断，不能因无法记账而放行。

### 7.2 重建传输

同一目标仍授权且用户未主动断开时可有界重连；需要新登录认证则走客户端私密流程。网络连接层重试和业务操作重试分离：未交接可按规则重试，已交接未知不能自动重跑。

新连接不恢复旧 Shell、旧批准、旧密码或挑战。按 §2 恢复显式上下文，向模型与 UI 报告连接已重建、恢复状态、未决项和允许的下一步。“连接成功”绝不意味着旧写入已完成。

### 7.3 继续核验，不等于继续写入

独立只读入口受控查询原目标和作业，证据引用关联原尝试。不能从服务 active 推出正确版本、从新连接推出旧操作未执行、从文件存在推出内容一致、从人工历史推出业务效果。

证据足够：提交对账 → 收 ACK → 同步解除确切项 → 当前任务若仍处于允许自动核验的控制代次，继续下一步决策；用户已停止则不唤醒。

证据不足：保留写锁，允许明确风险决定。当前仍可信运行的作业不可人工确认消失。用户的「接受此风险并继续」由单一后端用例执行，检查 ACK、锁、其他未决项、权限、控制代次和预算。重复点击、超时和迟到响应不重复执行；原操作仍保持未知，不重放、不自动批准后续操作。仅接受并解除不等于续跑，拒绝则保持阻断。

跨任务风险域沿用可信主机谱系/修订关系，不仅凭地址字符串合并。换任务、终端、身份、连接或将来子代理都不能绕锁；Journal 仍按任务/主机授权裁剪，不能以跨任务锁为由泄露其他对话。风险卡只展示处理该项所需的脱敏摘要和按需证据。

## 8. 人工终端与混合审计

人工与 AI 使用独立 Shell/输入权限。人工 export 不影响 AI 上下文；人工修改真实文件会影响后续观察，AI 需读回而非假定部署期间机器无人改动。AI 队列不冻结人工操作；文件版本冲突与校验失败必须如实处理。

人工终端不走 AI 三模式裁决；登录信任、接收方、会话归属和 UI 动作仍校验。密码登录、私钥口令和 OTP 由专用通道提供；任意人工终端提示不能冒充 AI 的可信认证挑战。

记录会话开关、主机与连接变化、可识别命令起止/退出、显式引用及采集失效，标 actor=human。Shell 集成只能证明其支持范围内的事件；嵌套 Shell、vim、数据库客户端、tmux、关闭钩子等标明盲区，不声称完整捕获操作或效果。

不记录全部按键来补齐盲区。安全脱敏后才能保存/查询正文；无法可靠处理敏感捕获时不向模型公开。人工审计权限与 AI Journal 权限独立，后者只见已授权主机、相关、有限的摘要/证据。时间线交织 AI、用户、系统事件并保留来源/因果，不承诺跨来源墙钟绝对顺序。

人工底座迁移在 G5 独立验收：不重做界面，不损失 xterm 输入、尺寸、全屏应用、关闭确认和手动连接体验；模型不获得人门 API，误投输入被拒。未过门保留当前人工路径，不给新 AI 复用作为兜底。

## 9. 多主机与池的演进

首版从入口限制单主机授权，但逻辑键、上下文、作业、卡片和审计包含 task/host；以双主机 fixture 验证隔离，不提前建立跨主机协调器。

后续开放时：每台主机独立授权/身份/限额，不让同一文本 hostId 充当许可；同主机风险域跨任务共享写入准入，不同主机可并行。池仅复用匹配用途和代次的空闲物理资源，不复用另一任务的 Shell、密码或批准。多主机验收通过才允许子代理并行。

## 10. Go 候选的准入条件

Go 不属于 G0–G5 发布前置。另行立项前必须有原生路径实测不足，以及可度量的作业观察/停止收益；不能只以“更快”或语言偏好推动。

若立项：

- 用户明确开启/部署/更新/卸载；AI 可建议但不能自主生效。产品级变更权限不受模式三放开，任务内业务变更仍按各门裁决。
- SSH 复用，不开新端口、不引入独立凭据、不常驻监听；远端不存密码或私钥。
- Linux amd64/arm64 分别验证，矩阵含可信版本快照、产物完整性和协议握手；静态单件仍有内核、CPU、ABI、noexec/文件系统及安全策略下限。
- 执行器不做业务裁决，但要验证协议、参数与接收合法性；“哑”不意味着接受任意损坏请求。
- 同工具与结果协议，不伪造双模相同观察能力。无矩阵/部署失败只能在**确定业务未交接**时选原生；已交接或边界不明一律核验，不自动换路重跑。
- 降级原因可审计，必要时报告能力变化；原生也不支持时如实返回，不承诺任何主机都可完成任务。

## 11. 验收矩阵与实施停止条件

| 领域 | 必测证据 |
|---|---|
| 连续性 | 参数修正、替代缺工具方案、普通失败不 abort；拒绝不换写法绕过；取消不索密；用户停止不自动继续 |
| 身份 | §3 五分支的 fixture 与获准真 PAM 对照；未知不 su 回退，当前 root 不多问认证 |
| 上下文 | 单次/默认 cwd 区分，重建/目录丢失/身份变化，环境修订失效；reset 不解锁 |
| 文件 | 普通/root 身份、创建/更新、摘要冲突、元数据限制、并发人工修改、提交中断与恢复目标变化 |
| 作业 | 无输出长跑、输出上限、停止请求/退出分离、断线未知、PID 复用/身份变化不误发停止 |
| 能力卡 | 最小 Linux、缺字段/超时、未知权限不过早判不可能、旧探测迟到、重连失效、压缩后 Journal 恢复 |
| 恢复 | 交接前后断线、迟到退出、跨任务锁、风险 ACK 失败/丢失、仅解除与接受并继续、用户停止后迟到核验 |
| 人工 | 输入隔离、全屏/尺寸/关闭行为、混合时间线、盲区/敏感正文不外流 |

每项标明单元、协议 fixture、真实 SSH/PAM 或应用健康证据；模拟通过不能替代真机。原生可信阶段、特权文件提交或作业控制若达不到要求，保留安全失败并在阶段报告列阻塞，不能私自恢复远端 Python、引入 helper、扩大模式权限或跳过核验。
