# Agent 重构 G1-D · 审批等待释放执行槽

> 状态：本批实现、全量自动回归与构建通过。承接 [G1-C 审批权威迁移](AGENT_REFACTOR_G1_APPROVAL_REPORT.md)。本批不声称完成整个 G1，也不授权真实主机操作。

## 行为

审批挂起时释放 OperationScheduler 的并发/写入容量；用户同意后重新加入该 lane 队尾，拿回槽位后才返回 SafetyGate，重查策略、终端代次、控制状态及审批硬截止。拒绝/取消/失效无需占回槽位即可收尾。这个重新准入不是再次询问用户，不生成新的批准或绕过主机未决锁。

SafetyGate 通过可选的等待观察钩子交给受控调度器暂停容量；实际等待仍由 Application ApprovalCoordinator 负责。工具和 Renderer 不获得槽位或许可句柄。没有使用该钩子的调用方沿原路线运行，不自动赋予并发能力。

已停放但未完成的 pipeline 持有 lane 生命周期引用，避免活动队列一度清空后创建第二个独立 lane。排队恢复时取消，会移除自身队列项而不减掉其他操作的槽位；后续工作能继续。

## 限制

- 不把调度顺序当授权；风险分类、主机串行锁、业务审计 ACK 与最终派发复核保持原链路。
- 不会抢占已在运行的远端操作；审批前产生的其它合法操作仍受各自权限和写锁约束。
- 审批恢复后检查硬截止，不把执行中正常超过审批时限直接当成远端退出。主机队列中单次派发许可与完整耐久契约仍需后续统一验收。
- 只释放等待用户裁决的容量；本批没有将模型独立审核、私密认证或业务执行伪装成空闲容量。
- 原生可信未启动证据仍未建立；G1-A 的保守认证分类不变。

未连接真实 SSH/PAM，未调用付费模型，未提交或推送。
