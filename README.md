# CloudHelm

CloudHelm 是一个带 AI 助手的桌面 SSH 客户端，面向个人开发者和运维人员。你可以像平常一样连接服务器、使用终端，也可以在右侧用自然语言描述目标，让 AI 调查、提出操作、经过审核后执行，并根据实际结果继续分析和验证。

**不需要先创建任务。** 点击主机打开终端，直接开始对话；后台自动记录操作与审核过程。每个新对话只绑定发起时的一台主机，未连接主机的自由对话不能操作远端。

当前版本为 **0.2.3，开发中**，采用 [AGPL-3.0-only](LICENSE) 许可证。桌面构建目标为 macOS Apple Silicon、macOS Intel 和 Windows x64；自动测试与真实环境验收的区别见[验收状态](docs/STATUS.md)。

## 可以做什么

- **正常使用 SSH**：SSH Agent、私钥或密码认证，主机指纹核对、单跳板机、多个可关闭终端标签和只读 SFTP 文件页。
- **方便管理主机**：主机行的“⋯”打开编辑和安全设置；私钥可通过系统文件选择窗口选择；“测试连接”直接测试未保存的配置。
- **右键菜单与快捷键**：终端、消息、代码块、主机与对话列表、标签页都有右键菜单，菜单右侧显示当前快捷键；键位可在“设置 → 快捷键”中按键录制修改。
- **引用与长粘贴**：选中文字或最后一条命令及输出可一键引用给 AI（运行中按点击时刻取快照）；超过 10 行或 1,000 字符的粘贴自动折叠为标签，可预览、编辑、复制、剪切与撤销重做，发送前按模型容量自动处理。
- **让 AI 协助操作**：Pi SDK 驱动多轮调查、规划、命令执行、结果分析和验证。AI 使用独立真实 SSH PTY，普通终端与 AI 终端互不抢占。
- **查看并接管执行**：审核通过后显示完整命令、用户名／主机／目录提示符和实际输出；在 AI 终端输入即可接管。暂停 AI、停止命令和断开 SSH 是不同操作。
- **按需使用 sudo**：支持普通 sudo 和可静态解析的前台命令列表，仅在服务器实际要求密码时通过独立窗口输入；AI 命令需要远端 Python 3。
- **选择审核方式**：低风险白名单自动通过，其余操作按主机设置走人工审核、AI 审核或自动执行；已识别的硬禁令在所有档位拦截。
- **配置自己的模型**：双列 Pi 供应商设置，分别填写 API Key、Base URL 和模型，支持测试连接；对话中可切换模型与思考强度。Jev 审核独立配置；订阅登录尚未开放。
- **读懂结果**：助手回复渲染 Markdown，代码块可复制；错误用友好弹窗说明。完成远端工作后，AI 提交验证证据、访问方式、变更与恢复说明供验收。

例如，在已连接的主机旁输入：

> 帮我检查这个服务的启动方式，把它容器化并启动。先查看现有配置，完成后给我访问地址、验证结果和恢复方法。

这是产品目标场景；真实模型自主完成整套部署的验收尚未完成，不应将本地模拟模型测试当作部署质量保证。

## 开始使用

1. 添加主机，填写地址、端口、账户和认证方式；私钥方式可点击“选择文件”。
2. 点击“测试连接”。如出现指纹确认，通过可信渠道核对后继续；测试不会保存配置，也不会打开终端。
3. 保存主机，点击左侧主机行连接服务器。
4. 在“设置 → API Key”中配置 API Key、地址和模型，测试后保存为默认。
5. 在右侧直接提问或描述要完成的操作；审核和交互请求会在界面中提示。

完整操作说明、模型切换和故障排查见[使用指南](docs/USER_GUIDE.md)。

## 获取与运行

有权限访问仓库 Actions 的用户可在成功的 **CI** 运行中下载构建产物：

| 平台 | Artifact 名称 | 内容 |
| --- | --- | --- |
| macOS Apple Silicon | `CloudHelm-macos-arm64` | DMG |
| macOS Intel | `CloudHelm-macos-x64` | DMG |
| Windows x64 | `CloudHelm-windows-x64` | NSIS 安装 EXE |

产物保留 7 天。当提交更新根目录 `version.json` 的版本号并推送到 `dev` 分支（开发仓库主线；总仓库的默认分支同理）时，CI 会自动把三平台安装包发布到 [GitHub Releases](https://github.com/TianJiaJi/CloudHelm/releases)（标记为预发布；说明正文取自 [CHANGELOG.md](CHANGELOG.md) 对应版本的更新日志，末尾附加自动提交清单，缺条目时回退为纯自动生成）；未更新版本号的提交只构建、不发布。发布失败或中断需要补发时，可在 Actions 手动运行 CI 并勾选 `force_publish`，为标签尚未创建的当前版本补建预发行。安装包当前未签名／公证。CI 构建成功不等于安装和所有交互流程已完成人工验收。

修改版本号只需编辑根目录 `version.json` 并提交：`pnpm install` 会启用 pre-commit 钩子（`.githooks/pre-commit`），提交时自动把版本同步进各包 `package.json` 与 README 说明并一并暂存；也可手动运行 `pnpm version:set`。`pnpm version:check` 在 CI 中兜底校验一致性。更新版本号后请在 [CHANGELOG.md](CHANGELOG.md) 补写该版本的更新内容（上一版本到本版本之间的全部更新）；忘了写不拦截，提交升版时钩子会自动补一条「修复了一些已知问题」默认条目，之后可继续润色。

从源码启动需要 Node.js 24、pnpm 11.9.0，以及本平台原生模块构建工具：

```sh
pnpm install --frozen-lockfile
pnpm dev
```

测试、打包、Windows 构建环境和贡献流程见[开发指南](docs/DEVELOPMENT.md)。

## 安全与数据

所有 Agent 远端变更都经过统一安全入口。第二档优先通过 Vercel Gateway 调用 `typesafe-ai/jev`；未配置 Jev Key 时，由当前主模型发起独立审核。已配置 Jev 但服务故障时转人工，不静默换用模型。模型和 Gateway 的使用费用由对应供应商收取，CloudHelm 当前没有订阅计费功能。

命令审核是对已识别风险的防护，不能保证识别任意脚本的最终效果，也不是远端沙箱。人工手动输入不受 Agent 审核档位约束。模型服务会接收完成对话和审核所需的操作上下文；详情见[安全与数据边界](docs/SECURITY.md)。

### AI 执行与 root 会话

AI 按一个逻辑动作一次调用执行，使用 `cwd` 指定目录，分别完成创建、写入和验证。
这是提示词规范，底层保持对既有复合命令的兼容；过滤单一查询的管道仍可使用。
权限依据当前主机实际情况判断：优先使用单条 `sudo`，需要密码时由专用认证窗口接收。
成功验证的密码可在当前任务、主机、身份和终端内存复用最多 5 分钟，不落盘；暂停、断线、认证失败或任务结束即清除。每次命令仍独立审核。
普通权限不足与认证失败、未启动、可能部分完成分开返回；未知结果必须核验，不自动重放。

当 sudo 不可用时，AI 可提出 `request_root_session`。窗口显示主机、目录、原因和待执行命令，
由用户选择 **SSH 登录 root** 或 **通过 su 切换 root**。会话建立只执行身份核验，
后续操作仍逐条经过 SafetyGate。会话仅限本任务本轮，结束、暂停、断线或接管后失效。
身份变化使旧批准失效；原普通用户 SSH 连接不会被替换。

- root SSH 使用原主机地址、指纹、跳板以及已选择的认证方式（密码、私钥或 SSH Agent）。
  不复用普通账户保存的密码；新密码/私钥口令通过专用窗口提供，本次不保存。
  服务器必须允许该 root SSH 认证方式。
- `su` 后备针对 Linux 的 `/usr/bin/su`、Python 3 和 Unix socket peer credentials。
  认证 PTY 与业务命令输入隔离；不支持的认证交互关闭会话，需用户处理。
  `su` 不提升普通用户 SFTP 权限；需要时先暂存非秘密文件，再执行经审核的 root 安装命令。
- 审核拒绝、认证失败/取消、停止和断线不会触发自动换账号重试。关闭会话不证明远端进程已经退出。

### 开发诊断日志

`pnpm dev` 默认将脱敏后的用户/AI 聊天、工具调用、审核结论、执行身份、退出码及认证状态
输出到启动终端，同时写入 `<userData>/logs/dev/runtime.jsonl`。启动时打印具体目录。
单文件上限 10 MiB，包含当前文件共保留 5 个；目录权限为 0700，文件权限为 0600。

环境变量：

- `CLOUDHELM_LOG_LEVEL=debug|info|error|off`：开发默认 `debug`，正式构建默认 `off`。
- `CLOUDHELM_LOG_DIR=/absolute/path`：覆盖日志目录。
- `CLOUDHELM_USER_DATA=/absolute/path`：已有的应用数据目录覆盖选项，也影响默认日志位置。

按 `taskId`、`hostId`、`operationId`、`requestId` 关联事件。认证回答、密码、验证码、私钥、
原始 IPC/模型配置、模型内部推理和文件写入正文不作为诊断事件记录；文本中的常见秘密字段额外脱敏。
日志写入失败不改变远端审核策略。诊断日志不同于已有的操作审计和终端日志。
